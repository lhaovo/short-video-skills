# 短视频总控台

一条片子从故事到发布，只在一个目录里发生。这个技能管三件事：**目录怎么建、阶段怎么走、每段什么算过关。**

它不教怎么写故事或怎么改编分镜（那分别由 `ai-novel-short-story` 与 `short-story-to-drama-storyboard` 负责），不替代生成模型，不做剪辑实操。它保证的是：**任何一次制作，打开目录就知道做到哪一步、下一步做什么、能不能往下走。**

---

## 一、阶段

```
S1A 短篇故事 → G1-A → S1B 短剧分镜 → G1-B
                                           ↓
S2 提示词 → G2 → S3 生成 → G3 → S4 交付 → G4 → S5 发布 → G5 → 完成
```

| 阶段 | 做什么 | 主要产物 | 谁来干 |
|---|---|---|---|
| S1A 短篇故事 | 从想法到完整短篇故事；已有故事可跳过 | `01-故事/story.md` 与同目录过程文件 | `ai-novel-short-story` |
| S1B 短剧分镜 | 把定稿故事改编为单集短视频或系列短剧，产出可拍分镜 | `01-故事/drama/storyboard.md` 与结构化记录 | `short-story-to-drama-storyboard` |
| S2 提示词 | 分镜 → 资产清单 + 生成清单 | `02-资产清单.md`、`03-生成清单.md` | `short-video-prompt` |
| S3 生成 | 先备资产，再出分段视频 | `04-素材/` | `short-video-assets` + `short-video-generate` |
| S4 交付 | 拼段、字幕、配乐、混音 | `05-成片/` | 剪辑工具 |
| S5 发布 | 标题、封面、话题、时间、标识 | `06-发布包.md` | 本技能 |

**一次只推进一段。** 跳段是返工最主要的来源——G2 没过就去生成，出来的素材一定对不上镜号。

## 二、目录规范（本技能是唯一权威）

所有产物进同一个目录，默认位置在项目根 `outputs/` 下。**其他环节不再自己定义目录规则，一律服从本节。**

### 2.1 结构

```
outputs/
└── 2026-09-29-睡不够像多动症/
    ├── 00-流程状态.md
    ├── 01-故事/
    │   ├── story.md
    │   ├── plan.md
    │   ├── state.json
    │   └── drama/
    │       ├── source.story.md
    │       ├── adaptation.md
    │       ├── scripts/
    │       ├── storyboards/
    │       └── storyboard.md
    ├── 02-资产清单.md
    ├── 03-生成清单.md
    ├── 04-素材/
    │   ├── 01-资产图/
    │   ├── 02-首帧/
    │   └── 03-片段/
    ├── 05-成片/
    │   └── 成片-v1.mp4
    └── 06-发布包.md
```

编号前缀的用处：目录一打开，文件按流程顺序排；做到哪一段、缺哪一段，扫一眼就知道，不需要额外的导航文件。

### 2.2 目录名

格式固定：`YYYY-MM-DD-标题`

| 项 | 要求 |
|---|---|
| 日期 | **建目录当天**，之后不再变 |
| 分隔 | 日期与标题之间一个连字符；标题内部也用连字符连接词语 |
| 长度 | 标题 8–15 字 |
| 禁用 | 斜杠、反斜杠、冒号、星号、问号、引号、尖括号、竖线、空格与标点 |
| 重名 | 同一天同一标题，追加 `-2`、`-3` |

标题取**选定命题里最有辨识度的短语**，不取品类名：

| 不行 | 可以 |
|---|---|
| 科普干货 | 睡不够像多动症 |
| 抖音短视频 | 热饭外面烫里面凉 |
| 10月22日选题 | 保温杯装咖啡半天就凉 |

判断方法：**三个月后只看目录名，能不能想起这是哪条片子。** 品类名三个月后一定想不起来，命题可以。

### 2.3 三条铁律

1. **目录名建好就不再改。** 改了，素材引用路径立刻断一批。要换标题，改 `06-发布包.md` 里的发布标题，不动目录。
2. **跨天也不改日期。** 第二天接着做，目录还是建目录那天的日期，不另开一个目录。
3. **一条片子一个目录。** 系列片、矩阵裂变不做成子目录，另开目录，标题加区分词。

### 2.4 开工第一步

用户说「开一条新的」时，先问齐三样，再建目录：

- 平台（抖音 / 视频号 / 小红书）
- 目标时长
- 一句话方向，或已经定稿的短篇故事

然后按顺序做四件事：

1. 按 2.2 生成目录名，**念给用户确认**——这是唯一一次改名不付代价的机会
2. 建目录，以及 `04-素材/01-资产图`、`02-首帧`、`03-片段`、`05-成片` 四个子目录
3. 写 `00-流程状态.md`：当前阶段 = S1A，填写项目验收画像，G1-A、G1-B、G2–G5 全填「未开始」
4. 转 S1A；已有定稿故事时从 S1B 开始

没确认名字就先建，后面改名的成本由用户承担。

## 三、状态文件

`00-流程状态.md` 是这条片子的存档点。**每次推进阶段后立刻更新**，不攒着。

必须有的字段：

| 字段 | 作用 |
|---|---|
| 目录名、创建日期、平台、目标时长 | 定位 |
| 当前阶段 | 七选一：S1A / S1B / S2 / S3 / S4 / S5 / 已完成 |
| 门禁结果 | G1-A、G1-B、G2–G5 逐条：过 / 未过 / 未开始 |
| 产物清单 | 已有文件 + 缺失文件 |
| 阻塞项 | 现在卡在哪、等谁 |
| 项目验收画像 | 内容类型、目标、节奏意图、最长无台词区间上限、静默承载方式、硬约束、验收人/定版条件 |
| 版本记录 | 每次改动一行：日期 + 改了什么 + 为什么 |

模板见 `assets/flow-state-template.md`。

它解决一件很具体的事：**换会话、隔一周、换人接手，读这一个文件就能续上。** 没有它，第三天回来得把素材翻一遍才想得起做到哪。

---

## 四、门禁

门只有两种结果：过、不过。不过就停在这一段，不许「先做着看」。

### G1-A · 短篇故事过关（S1A → S1B）

- `01-故事/story.md` 是连续成文，不含内部分段标题、创作说明或审查记录
- 故事已完成 `ai-novel-short-story` 的整篇审查与必要修复，`review.md` 无未解决 critical 问题
- `story_state.py status` 与 `validate` 均通过；用户已确认故事定稿
- 故事的标题、主角目标、核心问题、必须保留事实和结局承诺足以支撑改编
- 平台、单集目标时长和发布形态已确认；系列短剧还要确认集数

### G1-B · 短剧分镜过关（S1B → S2）

- `01-故事/drama/source.story.md` 与已确认的 `01-故事/story.md` 一致，创建后源故事未被静默替换
- `adaptation.md` 写明必须保留事实、允许改动、角色视觉锚点与剧情定位
- 每集脚本已通过质量门：`approved` 或带可见风险的 `continue_with_warning`
- `storyboard.md` 与 `storyboards/*.json` 完整、镜号连续，覆盖开场钩子、反应、信息揭示、决定性动作、反转和集尾压力
- 单集短视频为 1 集、20–300 秒；系列为 2–40 集、每集 20–300 秒
- 分镜中的角色、地点、道具、时间与知识状态和脚本一致；角色视觉锚点已写入改编契约
- `drama_state.py status` 与 `validate` 均通过；用户已确认要进入视频生成的分镜版本
- 项目验收画像已填写；平台、目标时长或硬约束未确认时，记录用户授权的默认值，否则停在 S1B

### G2 · 生成清单过关（S2 → S3）

- 每条提示词都有对应镜号，没有多出来的一段
- 各段时长合计与分镜总时长相差 ≤1 秒
- 清单引用的资产编号，在资产清单里都有定义，无悬空引用
- 主模式已定死：**首尾帧 或 参考图，二选一**；文生只用于无主体镜头
- 产品参数、包装、logo 这类镜头已标注「必须用真实图」，不交给纯文生视频
- **有台词的段，台词原文已写进提示词，与分镜台词逐字一致**（人物对白不再独立配音，漏了这段就无声）
- 每段提示词的“画面字段”表写明主体、状态、动作、环境、光线、景别、机位/角度、运镜和依赖/可见事实；不适用项说明原因
- 分镜关键可见事实、前置依赖和时长意图已映射到首帧或段内动作

### G3 · 素材过关（S3 → S4）

- 每段都有可用版本，缺的写进阻塞项
- 产品几何不变形、标签可读不改字
- 相邻段首尾能接：同一只产品、同一光线方向、同一画幅
- IP/角色特征清单里的标志性识别点及数量，已在定版片段中逐镜核对
- 同一镜有多个候选时，选定版本已写进清单
- **带台词的段已逐句听核：没有漏句、关键字没念错**
- 定版台词结论已记录在 04-素材/00-台词定案.json，含糊关键字的转写多数仅作人工听核辅助
- 已按时间顺序完成人工全片素材审看，检查跨段因果、角色/道具状态、空间连续性和节奏；生成前首帧故事板不能替代本项
- 有定版片段台词时间轴时先做节奏预检；没有成片字幕时记录待 S4 实测，不把预检当成片结论
- 生成清单中的拟音、叠字等后期项均有 S4 执行计划，无悬空承诺

### G4 · 成片过关（S4 → S5）

- 实际时长与目标偏差 ≤10%
- 用成片字幕和实际时长运行本技能 scripts/check_rhythm.py，报告及听核结论附在 00-流程状态.md；字幕空档仅是无台词代理指标
- **字幕与实际听到的台词一致**（不是与原稿一致——念错时以听到的为准）
- 人声清晰，配乐不压人声
- 画幅、分辨率、帧率符合目标平台要求
- 成片最长无台词区间以人工听核为准、字幕空档报告辅助定位；超过验收画像声明值且未在分镜声明为非语言段的，退回
- 声明允许长静默的区间，在分镜中写明动作、拟音、音乐或氛围承载，并在交付产物中标出对应文件与时间点
- 生成清单承诺的后期项均已完成并能定位产物，或有明确的验收人豁免

### G5 · 发布前过关（S5 → 完成）

- 强监管类目（药品、保健、器械、金融、教育）已另行审核
- AI 生成内容已按平台要求做标识
- 标题、封面、话题、发布时间齐备
- 无个人信息、无未授权肖像与场地

## 五、交接卡

阶段之间只通过文件交接，不靠「刚才我们说到哪」。每段结束时填一张卡，写进状态文件的「交接」栏：

| 交接 | 卡里必须有 |
|---|---|
| S1A → S1B | `story.md`、剧情命题、主角目标、必须保留事实、结局承诺、用户已确认的改动 |
| S1B → S2 | `storyboard.md`、当前集结构化分镜、改编契约、角色视觉锚点、关键实体/规格与必须真实呈现的信息 |
| S2 → S3 | 每段的生成任务：段号、时长、提示词、参考图编号、模式、候选数 |
| S3 → S4 | 素材清单：文件名、段号、时长、可用性；台词是否逐段听核过、BGM 是否已选 |
| S4 → S5 | 成片文件、时长、画幅、封面素材、卖点与话题词 |

完整字段见 `references/stage-specs.md`。

## 六、续做一条没做完的片子

用户说「接着做那条睡不够的」这类话时：

1. 列 `outputs/` 下的目录，按名字匹配；匹配不上就问一句，别猜
2. 读 `00-流程状态.md`，**先只看当前阶段与阻塞项**；若停在 S1A/S1B，再运行对应 skill 的 `status`，从第一个未完成阶段续做
3. 汇报三行：做到哪、卡在哪、下一步做什么
4. 得到确认后再进对应阶段

不要从头重做一遍。也不要跳过状态文件直接推理阶段——推错会把已过的门重开一次。

## 七、与子技能的关系

| 层 | 谁 | 管什么 |
|---|---|---|
| 流程层 | 本技能 | 目录、阶段、门禁、状态、交接 |
| 故事层 | `ai-novel-short-story` | 想法 → 三方向 → 因果规划 → 连续短篇故事 → 整篇审查 |
| 改编分镜层 | `short-story-to-drama-storyboard` | 定稿故事 → 改编契约 → 剧集脚本 → 质量门 → 逐镜分镜 |
| 提示词层 | `short-video-prompt` | 短剧分镜 → 资产清单 + 生成清单 |
| 资产层 | `short-video-assets` | 清单 → 图：排产、出候选、验收、落盘 |
| 生成层 | `short-video-generate` | 清单 → 片段：建任务、轮询下载、媒体体检、台账 |
| 交付层 | 剪辑工具 | 拼接、字幕、配乐、混音 |

三条规则：

- **故事层与改编分镜层不另建平行制作流程**，由本技能传入 `01-故事/` 与 `01-故事/drama/`，产物归入同一制作目录
- **提示词层不重新编排内容**，只做翻译；本技能不复制它的作业法
- **资产层不改内容和提示词**，只管图做出来、对得上、验得过
- **生成层不改视觉设计**，只让已定画面动起来，并留下可追溯的任务记录
- **流程层不改写任何层的写作规范**，只判它过不过门

冲突时：目录与文件名以本技能为准；故事判断以 `ai-novel-short-story` 为准，改编与分镜判断以 `short-story-to-drama-storyboard` 为准。

---

## 八、边界

- **不写故事与分镜规范**：故事创作和短剧分镜写法在对应层，本技能不重复
- **不替代生成模型**：写清任务与验收标准，不保证某一次生成一定成功
- **不做剪辑实操**：规定成片标准，具体拼接在剪辑工具里完成
- **不承诺流量**：阶段门禁保证「流程没漏、素材能接、发布合规」，不保证数据
- **不替代平台规则与法律审核**：平台政策与法规会变，强监管类目必须另行确认
