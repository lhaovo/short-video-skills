# 短视频总控台

一条片子从故事到发布，只在一个目录里发生。这个技能管三件事：**目录怎么建、阶段怎么走、每段什么算过关。**

它不教怎么写故事或怎么改编分镜（那分别由 `ai-novel-short-story` 与 `short-story-to-drama-storyboard` 负责），不替代生成模型，不做剪辑实操。它保证的是：**任何一次制作，打开目录就知道做到哪一步、下一步做什么、能不能往下走。**

**流程顺序锁：必须按 S1A → S1B → S2 → S3 → S4 → S5 推进。任何现有故事、现成分镜、现成素材都不能成为跳步理由。** 进入下一阶段前先更新门禁并运行顺序检查；检查不通过就停在当前阶段。

**用户停点协议：默认一次用户回复只授权一个阶段。** 到达任何用户停点后，必须先完成技术检查，再直接呈现当前版本，把门禁状态设为「等待用户确认」，然后结束当前回合等待用户回复。“继续吧”只表示批准当前门禁并进入下一阶段，不能解释为自动跑完剩余流程。进度消息不算停点，也不能代替用户批准。

## 一、阶段

```
S1A 短篇故事 → G1-A → S1B 短剧分镜 → G1-B
                                           ↓
S2 提示词 → G2 → S3 生成 → G3 → S4 交付 → G4 → S5 发布 → G5 → 完成
```

| 阶段 | 做什么 | 主要产物 | 谁来干 |
|---|---|---|---|
| S1A 短篇故事 | 从想法生成故事，或接收已有故事；无论来源都必须完成故事接收、审查/去味和 G1-A | `01-故事/story.md` 与同目录过程文件 | `ai-novel-short-story` + `story-deslop` |
| S1B 短剧分镜 | 把定稿故事改编为单集短视频或系列短剧，产出可拍分镜 | `01-故事/drama/storyboard.md` 与结构化记录 | `short-story-to-drama-storyboard` |
| S2 提示词 | 分镜 → 资产清单 + 生成清单 | `02-资产清单.md`、`03-生成清单.md` | `short-video-prompt` |
| S3 生成 | 先备资产，再出分段视频 | `04-素材/` | `short-video-assets` + `short-video-generate` |
| S4 交付 | 拼段、字幕、配乐、混音 | `05-成片/` | 剪辑工具 |
| S5 发布 | 标题、封面、话题、时间、标识 | `06-发布包.md` | 本技能 |

**一次只推进一段。** 跳段是返工最主要的来源——G2 没过就去生成，出来的素材一定对不上镜号。

**技术通过不等于门禁通过。** 脚本检查、抽帧、听声、选片和 Agent 复核只能写入「技术/Agent检查」；只有用户明确确认后，`门禁状态` 才能从「等待用户确认」改成「已批准」。

## 二、目录规范（本技能是唯一权威）

所有产物进同一个目录，默认位置在项目根 `outputs/` 下。**其他环节不再自己定义目录规则，一律服从本节。**

### 2.1 结构

```
outputs/
└── 2026-09-29-睡不够像多动症/
    ├── 00-流程状态.md
    ├── 01-故事/
    │   ├── story.md
    │   ├── plan.md
    │   ├── state.json
    │   └── drama/
    │       ├── source.story.md
    │       ├── adaptation.md
    │       ├── scripts/
    │       ├── storyboards/
    │       └── storyboard.md
    ├── 02-资产清单.md
    ├── 03-生成清单.md
    ├── 04-素材/
    │   ├── 01-资产图/
    │   ├── 02-首帧/
    │   └── 03-片段/
    ├── 05-成片/
    │   └── 成片-v1.mp4
    └── 06-发布包.md
```

编号前缀的用处：目录一打开，文件按流程顺序排；做到哪一段、缺哪一段，扫一眼就知道，不需要额外的导航文件。

### 2.2 目录名

格式固定：`YYYY-MM-DD-标题`

| 项 | 要求 |
|---|---|
| 日期 | **建目录当天**，之后不再变 |
| 分隔 | 日期与标题之间一个连字符；标题内部也用连字符连接词语 |
| 长度 | 标题 8–15 字 |
| 禁用 | 斜杠、反斜杠、冒号、星号、问号、引号、尖括号、竖线、空格与标点 |
| 重名 | 同一天同一标题，追加 `-2`、`-3` |

标题取**选定命题里最有辨识度的短语**，不取品类名：

| 不行 | 可以 |
|---|---|
| 科普干货 | 睡不够像多动症 |
| 抖音短视频 | 热饭外面烫里面凉 |
| 10月22日选题 | 保温杯装咖啡半天就凉 |

判断方法：**三个月后只看目录名，能不能想起这是哪条片子。** 品类名三个月后一定想不起来，命题可以。

### 2.3 三条铁律

1. **目录名建好就不再改。** 改了，素材引用路径立刻断一批。要换标题，改 `06-发布包.md` 里的发布标题，不动目录。
2. **跨天也不改日期。** 第二天接着做，目录还是建目录那天的日期，不另开一个目录。
3. **一条片子一个目录。** 系列片、矩阵裂变不做成子目录，另开目录，标题加区分词。

### 2.4 开工第一步

用户说「开一条新的」时，先问齐三样，再建目录：

- 平台（抖音 / 视频号 / 小红书）
- 目标时长
- 一句话方向，或已经定稿的短篇故事

然后按顺序做四件事：

1. 按 2.2 生成目录名，**念给用户确认**——这是唯一一次改名不付代价的机会
2. 建目录，以及 `04-素材/01-资产图`、`02-首帧`、`03-片段`、`05-成片` 四个子目录
3. 写 `00-流程状态.md`：当前阶段 = S1A，填写项目验收画像，G1-A、G1-B、G2、G3-A、G3–G5 全填「未开始」
4. 一律进入 S1A。已有故事只改变 S1A 的生产方式，不允许直接进入 S1B

没确认名字就先建，后面改名的成本由用户承担。

## 三、状态文件

`00-流程状态.md` 是这条片子的存档点。**每次推进阶段后立刻更新**，不攒着。

必须有的字段：

| 字段 | 作用 |
|---|---|
| 目录名、创建日期、平台、目标时长 | 定位 |
| 当前阶段 | 七选一：S1A / S1B / S2 / S3 / S4 / S5 / 已完成 |
| 门禁结果 | G1-A、G1-B、G2、G3-A、G3–G5 逐条：未开始 / 进行中 / 等待用户确认 / 已批准 / 用户退回 / 已失效 |
| 产物清单 | 已有文件 + 缺失文件 |
| 阻塞项 | 现在卡在哪、等谁 |
| 项目验收画像 | 内容类型、目标、节奏意图、最长无台词区间上限、静默承载方式、硬约束、验收人/定版条件 |
| 版本记录 | 每次改动一行：日期 + 改了什么 + 为什么 |

模板见 `assets/flow-state-template.md`。

它解决一件很具体的事：**换会话、隔一周、换人接手，读这一个文件就能续上。** 没有它，第三天回来得把素材翻一遍才想得起做到哪。

### 3.1 顺序检查（推进前必跑）

到达门禁时，先完成技术检查，直接在对话中呈现结果，把该门 `门禁状态` 写成「等待用户确认」，然后结束回合。**在用户回复前，不运行「进入下一阶段」检查，也不修改当前阶段。**

收到用户明确确认后，再记录批准版本与授权范围，把同一门禁状态从「等待用户确认」改为「已批准」，然后运行：

```bash
python short-video-flow/scripts/check_sequence.py --dir <制作目录> --enter <目标阶段>
```

例如用户已批准 G1-A、当前仍在 S1A，准备进入短剧分镜时：

```bash
python short-video-flow/scripts/check_sequence.py --dir <制作目录> --enter S1B
```

- 退出码 `0`：可以进入目标阶段。
- 退出码 `2`：顺序、门禁或前置产物不合格，停止推进。
- 检查通过后，才把「当前阶段」改成目标阶段。
- 不允许一次跨两个阶段，例如从 S1A 直接进入 S2。
- 不允许静默回退；修改上游时先显式重置受影响的后续门禁和产物状态。

检查某个内部停点是否已经获得用户批准：

```bash
python short-video-flow/scripts/check_sequence.py --dir <制作目录> --gate G3-A
```

只有门禁状态为「已批准」且 `批准版本与范围` 非空时退出码才是 `0`。只有技术检查通过时，该命令必须返回 `2`。

## 四、用户可见交付

**凡是需要用户选择、确认、验收、授权付费生成或决定发布的内容，必须在对话中直接呈现可审阅文字，不能只落盘后让用户自己去找文件。** 文件是正式版本和追溯记录，对话是用户实际的审阅入口；两边内容必须一致。

| 节点 | 对话里至少直接给出 |
|---|---|
| 开工 | 项目名称、平台、时长、单集/集数、目标、硬约束、验收标准 |
| 故事方向 | 三个方向各自的核心体验、冲突、主角、结局承诺、风格 |
| 故事定稿 | `story.md` 的完整连续正文；去味后的代表修改和仍需处理项 |
| 短剧分镜 | 改编契约要点、本次确认范围的剧集脚本、完整可读分镜与集尾悬念 |
| 生成清单 | 资产清单、逐段总览表、每段完整视频提示词、候选数与成本风险 |
| 资产定版 | 核心角色、产品包装、空间母版、场景与首帧的采用版本；待补和失败项 |
| 素材与片段 | 视频候选版本、推荐版本、不可用原因、失败或需重做的段落 |
| 成片 | 文件名、时长、画幅、节奏与字幕结论，并提供可直接打开的成片链接 |
| 发布包 | 标题、封面文案、正文、话题、发布时间、AI 标识与合规结论 |

**默认用户停点：**

1. 项目开工：确认目录名、平台、时长、集数与验收标准。
2. 故事方向：用户选定三个方向之一。
3. G1-A：用户确认故事定稿与去味结果。
4. G1-B：用户确认当前集脚本与完整分镜。
5. G2：用户确认生成清单，并明确是否授权付费生成资产图。
6. G3-A：用户确认核心资产与首帧，并明确是否授权后续付费视频生成。
7. G3：用户确认视频素材、听核结论与选片结果。
8. G4：用户确认成片、字幕、声音和封面。
9. G5：用户确认发布包，并单独决定是否发布。

长内容不能只回复“已生成，见某文件”。可以先用 3–5 行摘要说明结论，再逐段/逐镜完整贴出；用户明确说只看某一段时才可缩小展示范围。呈现后必须把当前门禁设为「等待用户确认」，结束回合并等待回复。

落盘后内容有改动时，必须同步更新文件、把原批准标记为「已失效」，并再次把改动后的版本发给用户确认。旧版本的批准不能沿用。

## 五、门禁

每道门只有一个 `门禁状态`：未开始 / 进行中 / 等待用户确认 / 已批准 / 用户退回 / 已失效。技术检查单独记录，不冒充用户批准；不是「已批准」就停在这一段。

### G1-A · 短篇故事过关（S1A → S1B）

- S1A 已实际执行；即使是用户提供的故事，也已建立 `01-故事/story.md` 并完成故事接收与去味检查
- `01-故事/story.md` 是连续成文，不含内部分段标题、创作说明或审查记录
- 故事已完成 `ai-novel-short-story` 的整篇审查与必要修复，`review.md` 无未解决 critical 问题
- `story-deslop` 已在 finalize 前完成；检测脚本无未处理 blocking，或用户对忠实保留人工原文的跳过已记录
- 去味结果已通过 `segments/` 写回并重建 `story.md`，不是只改了随后会被覆盖的正文副本
- 生成型故事的 `story_state.py status` 与 `validate` 均通过；导入型故事没有生成状态机时，`01-故事/source-original.md`、`01-故事/story.md`、`01-故事/review.md` 必须同时存在，review 中记录来源、变更范围与去味结论
- 用户已直接看到完整故事并明确确认；G1-A 门禁状态为「已批准」，批准版本与范围已记录
- 故事的标题、主角目标、核心问题、必须保留事实和结局承诺足以支撑改编
- 平台、单集目标时长和发布形态已确认；系列短剧还要确认集数

### G1-B · 短剧分镜过关（S1B → S2）

- `01-故事/drama/source.story.md` 与已确认的 `01-故事/story.md` 一致，创建后源故事未被静默替换
- `adaptation.md` 写明必须保留事实、允许改动、角色视觉锚点与剧情定位
- 每集脚本已通过质量门：`approved` 或带可见风险的 `continue_with_warning`
- `storyboard.md` 与 `storyboards/*.json` 完整、镜号连续，覆盖开场钩子、反应、信息揭示、决定性动作、反转和集尾压力
- 单集短视频为 1 集、20–300 秒；系列为 2–40 集、每集 20–300 秒
- 分镜中的角色、地点、道具、时间与知识状态和脚本一致；角色视觉锚点已写入改编契约
- `drama_state.py status` 与 `validate` 均通过；用户已直接看到当前脚本与完整分镜并明确确认，G1-B 门禁状态为「已批准」
- 项目验收画像已填写；平台、目标时长或硬约束未确认时，记录用户授权的默认值，否则停在 S1B

### G2 · 生成清单过关（S2 → S3）

- 每条提示词都有对应镜号，没有多出来的一段
- 各段时长合计与分镜总时长相差 ≤1 秒
- 清单引用的资产编号，在资产清单里都有定义，无悬空引用
- 主模式已定死：**首尾帧 或 参考图，二选一**；文生只用于无主体镜头
- 产品参数、包装、logo 这类镜头已标注「必须用真实图」，不交给纯文生视频
- **有台词的段，台词原文已写进提示词，与分镜台词逐字一致**（人物对白不再独立配音，漏了这段就无声）
- 每段提示词的“画面字段”表写明主体、状态、动作、环境、光线、景别、机位/角度、运镜和依赖/可见事实；不适用项说明原因
- 分镜关键可见事实、前置依赖和时长意图已映射到首帧或段内动作
- 用户已直接看到完整资产清单与逐段提示词；G2 门禁状态为「已批准」，批准范围明确包含本轮图片生成预算
- 仅技术检查通过或门禁状态为「等待用户确认」时，不得进入 S3

### G3-A · 核心资产定版（S3 内部）

- 核心角色、产品包装、空间母版、场景与首帧均已生成采用版本
- Agent 已完成编号、几何、身份、印刷、画幅和连续性检查
- 用户已直接看到资产采用版本、并排比对和待补项
- G3-A 门禁状态为「已批准」，批准范围明确是否允许继续付费生成视频
- G3-A 未批准时，不开始视频批量生成

### G3 · 素材过关（S3 → S4）

- 每段都有可用版本，缺的写进阻塞项
- 产品几何不变形、标签可读不改字
- 相邻段首尾能接：同一只产品、同一光线方向、同一画幅
- IP/角色特征清单里的标志性识别点及数量，已在定版片段中逐镜核对
- 同一镜有多个候选时，选定版本已写进清单
- **带台词的段已逐句听核：没有漏句、关键字没念错**
- 定版台词结论已记录在 04-素材/00-台词定案.json，含糊关键字的转写多数仅作人工听核辅助
- 已按时间顺序完成人工全片素材审看，检查跨段因果、角色/道具状态、空间连续性和节奏；生成前首帧故事板不能替代本项
- 有定版片段台词时间轴时先做节奏预检；没有成片字幕时记录待 S4 实测，不把预检当成片结论
- 生成清单中的拟音、叠字等后期项均有 S4 执行计划，无悬空承诺
- 用户已直接看到定版片段、视频选片、听核结论和残余问题；G3 门禁状态为「已批准」

### G4 · 成片过关（S4 → S5）

- 实际时长与目标偏差 ≤10%
- 用成片字幕和实际时长运行本技能 scripts/check_rhythm.py，报告及听核结论附在 00-流程状态.md；字幕空档仅是无台词代理指标
- **字幕与实际听到的台词一致**（不是与原稿一致——念错时以听到的为准）
- 人声清晰，配乐不压人声
- 画幅、分辨率、帧率符合目标平台要求
- 成片最长无台词区间以 Agent 听核为准、字幕空档报告辅助定位，并由用户在前一阶段或 G4 验收中确认；超过验收画像声明值且未在分镜声明为非语言段的，退回
- 声明允许长静默的区间，在分镜中写明动作、拟音、音乐或氛围承载，并在交付产物中标出对应文件与时间点
- 生成清单承诺的后期项均已完成并能定位产物，或有明确的验收人豁免
- 用户已直接查看成片并明确确认；G4 门禁状态为「已批准」

### G5 · 发布前过关（S5 → 完成）

- 强监管类目（药品、保健、器械、金融、教育）已另行审核
- AI 生成内容已按平台要求做标识
- 标题、封面、话题、发布时间齐备
- 无个人信息、无未授权肖像与场地
- 用户已直接看到完整发布包并确认；G5 门禁状态为「已批准」
- 允许完成发布包不等于允许实际发布；真正发布仍需用户单独授权

## 六、交接卡

阶段之间只通过文件交接，不靠「刚才我们说到哪」。每段结束时填一张卡，写进状态文件的「交接」栏：

| 交接 | 卡里必须有 |
|---|---|
| S1A → S1B | `story.md`、命题与必须保留事实；G1-A 为「已批准」及其批准版本 |
| S1B → S2 | `storyboard.md`、当前集结构化分镜、改编契约、角色视觉锚点；G1-B 为「已批准」 |
| S2 → S3 | 生成任务、提示词、资产与成本范围；G2 为「已批准」并明确包含图片生成授权 |
| S3a → S3b | 核心资产与首帧采用版本；G3-A 为「已批准」并明确包含视频生成授权 |
| S3 → S4 | 素材清单、可用性、台词听核、选片与 BGM；G3 为「已批准」 |
| S4 → S5 | 成片文件、时长、画幅、封面与残余问题；G4 为「已批准」 |

完整字段见 `references/stage-specs.md`。

## 七、续做一条没做完的片子

用户说「接着做那条睡不够的」这类话时：

1. 列 `outputs/` 下的目录，按名字匹配；匹配不上就问一句，别猜
2. 读 `00-流程状态.md`，**先只看当前阶段与阻塞项**；若停在 S1A/S1B，再运行对应 skill 的 `status`，从第一个未完成阶段续做
3. 汇报三行：做到哪、卡在哪、下一步做什么
4. 如果门禁状态是「等待用户确认」，重新直接展示待确认版本并结束回合，不推进
5. 用户说“继续吧”时，只批准当前门禁并进入下一阶段；到下一道用户停点再次结束回合

不要从头重做一遍。也不要跳过状态文件直接推理阶段——推错会把已过的门重开一次。

续做时必须先确认当前阶段，再运行 `check_sequence.py`。即使文件里已经存在下游分镜或素材，也只能回到当前未完成的阶段，不能据此跳过 S1A、S1B 或生成清单。

如果用户明确说“从 Sx 连续做到 Sy”，只允许连续推进到指定阶段；付费生成和实际发布仍需各自的明确授权，除非用户在同一句里清楚授予。

## 八、与子技能的关系

| 层 | 谁 | 管什么 |
|---|---|---|
| 流程层 | 本技能 | 目录、阶段、门禁、状态、交接 |
| 故事层 | `ai-novel-short-story` | 想法 → 三方向 → 因果规划 → 连续短篇故事 → 整篇审查 |
| 文风质检层 | `story-deslop` | S1A 定稿前的表达、用笔与故事承接检查；不改变已定剧情 |
| 改编分镜层 | `short-story-to-drama-storyboard` | 定稿故事 → 改编契约 → 剧集脚本 → 质量门 → 逐镜分镜 |
| 提示词层 | `short-video-prompt` | 短剧分镜 → 资产清单 + 生成清单 |
| 资产层 | `short-video-assets` | 清单 → 图：排产、逐张生成、验收、失败重试、落盘 |
| 生成层 | `short-video-generate` | 清单 → 片段：建任务、轮询下载、媒体体检、台账 |
| 交付层 | 剪辑工具 | 拼接、字幕、配乐、混音 |

三条规则：

- **故事层、文风质检层与改编分镜层不另建平行制作流程**，统一在 `01-故事/` 与 `01-故事/drama/` 内交接
- **提示词层不重新编排内容**，只做翻译；本技能不复制它的作业法
- **资产层不改内容和提示词**，只管图做出来、对得上、验得过
- **生成层不改视觉设计**，只让已定画面动起来，并留下可追溯的任务记录
- **流程层不改写任何层的写作规范**，只判它过不过门

冲突时：目录与文件名以本技能为准；故事判断以 `ai-novel-short-story` 为准，文风判断以 `story-deslop` 为准，改编与分镜判断以 `short-story-to-drama-storyboard` 为准。

---

## 九、边界

- **不写故事与分镜规范**：故事创作和短剧分镜写法在对应层，本技能不重复
- **不替代生成模型**：写清任务与验收标准，不保证某一次生成一定成功
- **不做剪辑实操**：规定成片标准，具体拼接在剪辑工具里完成
- **不承诺流量**：阶段门禁保证「流程没漏、素材能接、发布合规」，不保证数据
- **不替代平台规则与法律审核**：平台政策与法规会变，强监管类目必须另行确认
