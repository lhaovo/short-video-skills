# 五阶段作业规格

配合 SKILL.md 使用。每段都按同一套结构写：**进来要有什么、做什么、出什么、什么算过关、交接什么、容易卡在哪。**

---

## S1 · 故事与短剧分镜

### 进来要有什么

| 项 | 没有怎么办 |
|---|---|
| 平台 | 必须问，不猜 |
| 目标时长 | 必须问；单集短视频必须在 20–300 秒 |
| 一句话方向、已定稿短篇故事，或既有项目文件 | 都没有，先聊方向，别建目录 |

### 做什么

分两段执行，前一段不通过就不能进后一段。

**顺序锁：所有项目从 S1A 开始。已有故事不是跳过 S1A 的理由；已有分镜也不是跳过 S1A、S1B 的理由。**

**S1A · 短篇故事**

- 没有定稿故事时，调用 `ai-novel-short-story` 从想法创作。
- 已有定稿故事时，仍在 S1A 内执行“故事接收”：把原文件保留为 `01-故事/source-original.md`，形成可审阅的 `01-故事/story.md`，记录来源与允许改动范围，再执行去味检查。
- 项目目录固定为 `<制作目录>/01-故事`；不要另建脱离制作目录的故事工程。
- 依次完成三方向选择、2–8 段因果规划、顺序写作、整篇审查和最多一次必要修复。
- 在 `story_state.py finalize` 之前调用 `story-deslop`。默认检查表达、用笔和故事承接；剧情级缺口退回 `ai-novel-short-story`。
- 去味修改必须写回受影响 `segments/NN.md` 并由 `story_state.py` 重建 `story.md`；不得只改会被覆盖的正文副本。
- 去味后复跑 `story_state.py validate`，并确认 `check-ai-patterns.js`、`check-degeneration.js` 没有未处理 blocking。
- 故事长度按实际素材在 3,000–30,000 非空白字符内确定；不能为了凑短视频时长强行删成梗概。

**S1B · 短剧分镜**

- 故事定稿后调用 `short-story-to-drama-storyboard`。
- 默认项目目录为 `<制作目录>/01-故事/drama`，源快照是 `01-故事/story.md`。
- 单集短视频固定 1 集、20–300 秒；系列短剧为 2–40 集，每集 20–300 秒。
- 依次完成改编契约、剧集大纲、逐集脚本、质量审查、逐镜分镜和 finalize。
- S1A 结束后必须通过 G1-A 才能进入 S1B。现成分镜只能作为 S1B 的参考输入，仍需完成本轮改编契约、质量门和可读分镜确认。

### 出什么

`01-故事/` 下保留完整可续做状态：

```text
01-故事/
├── state.json
├── directions.md
├── plan.md
├── segments/
├── story.md
├── review.md
└── drama/
    ├── state.json
    ├── source.story.md
    ├── adaptation.md
    ├── episodes.md
    ├── scripts/
    ├── quality/
    ├── storyboards/
    └── storyboard.md
```

故事和分镜的阶段交付必须在当前回复中直接呈现可审阅内容，不能只给路径。对话版本与落盘版本必须一致。

进入 S1B 前运行：

```bash
python short-video-flow/scripts/check_sequence.py --dir <制作目录> --enter S1B
```

### 什么算过关（G1-A / G1-B）

| 检查 | 判据 |
|---|---|
| G1-A 已执行 | S1A 必须实际运行；生成型故事有完整状态机，导入型故事有 `source-original.md`、`story.md`、`review.md` |
| G1-A 故事状态 | 生成型故事通过 `story_state.py status` 与 `validate`；导入型故事有四件接收记录。两种路径都要求 `story.md` 连续、无内部标题，审查无未解决 critical 问题 |
| G1-A 去味 | `story-deslop` 已完成；表达与用笔修改已写回 segments，脚本无未处理 blocking，或忠实保留人工原文的跳过已记录 |
| G1-A 用户确认 | 三方向选择、故事定稿或必要修改已由用户确认 |
| G1-B 源快照 | `drama_state.py check-source` 通过，定稿故事与 `source.story.md` 一致 |
| G1-B 改编契约 | 必须保留事实、允许改动、角色视觉锚点和剧情定位均已落盘 |
| G1-B 剧集质量 | 每个待拍剧集最新质量状态为 `approved` 或 `continue_with_warning` |
| G1-B 分镜完整 | `storyboard.md` 可读，`storyboards/NN.json` 镜号连续，角色、地点、动作、对白和关键可见事实可执行 |
| G1-B 验证 | `drama_state.py status` 与 `validate` 通过 |
| 验收画像 | 平台、单集时长、节奏意图、最长无台词区间、静默承载方式、硬约束与验收人已记录 |

**没过就别进 S2。** 故事因果或改编分镜错了，后面每一段都会跟着错一遍。

### 交接卡（S1A → S1B）

```
故事：01-故事/story.md
命题：主角目标 / 核心问题 / 结局承诺
必须保留：人设、关系、关键物件、不可改事实
改编限制：允许压缩、合并、重排的范围
去味结论：{已完成 / 已授权跳过}；{未处理 blocking 或残余风格风险}
用户确认：已确认 / 待确认
```

### 交接卡（S1B → S2）

```
短剧分镜：01-故事/drama/storyboard.md
结构化分镜：01-故事/drama/storyboards/NN.json
改编契约：01-故事/drama/adaptation.md
当前集：集号、目标时长、开场钩子、集尾转折
角色：角色名 + visual_anchor
关键实体：真名、型号、必须准确的参数或道具
必须真实呈现：包装、logo、规格数字、关键证据
不可出现：改编契约和用户给出的红线
```

### 容易卡在哪

- 故事还没定稿就改编 → 先完成整篇审查，不把故事草稿当源快照
- 只有小说直接拿去生成 → 先走 S1B 产出改编脚本与逐镜分镜
- 已有故事想直接进 S1B → 不允许；先完成 S1A 的故事接收、去味与 G1-A
- 现成分镜想直接进 S2 → 不允许；先按 S1B 重新确认改编契约、脚本和分镜版本
- 分镜镜号重排过，但下游还在用旧编号 → 交接卡和生成清单一起重发

## S2 · 提示词

### 进来要有什么

`01-故事/drama/storyboard.md`、当前集 `storyboards/NN.json`、当前集脚本和 `adaptation.md`，且 G1-B 已过。

进入 S2 前运行 `check_sequence.py --enter S2`；G1-A、G1-B 任一未通过就停止。

### 做什么

**作业法不在本技能内。** 本段调用 `short-video-prompt`，由它完成画面化、提资产、切段、组词、首帧与自检。

本技能在这一段只做三件事：

1. 把当前集分镜、脚本和改编契约交给它，并告知画幅、目标时长、**台词需原样写进提示词**
2. 收下它产出的 `02-资产清单.md`、`03-生成清单.md`
3. 按下面的 G2 逐条核，核过才放行到 S3

**加粗那一句是这次新增的。** 人物对白与旁白不再独立配音，说话人和台词必须在 S2 就落进提示词。如果这一步漏了，S3 生成出来就是无声或串角色片段，得整段重来。

### 出什么

**`02-资产清单.md`** —— 这次制作要准备哪些图，谁复用谁：

| 编号 | 类型 | 用途 | 来源 | 被哪些段引用 | 状态 |
|---|---|---|---|---|---|
| PR-01 | 产品主体 | 一致性母版 | 真实拍摄 | S01、S02 | 已有 |
| SC-01 | 场景 | 环境 | AI 生成 | S01、S03 | 待出图 |

**`03-生成清单.md`** —— 每段一条，可直接执行：

| 段号 | 镜号 | 时长 | 模式 | 引用素材 | 首帧 | 后期项 | 候选数 | 前置依赖/关键事实 |
|---|---|---|---:|---|---|---|---:|---|

两份清单落盘后，必须把资产总表、逐段概览、每段完整提示词、候选数和生成成本风险直接贴回对话。不能只回复文件路径；用户应先看到要生成什么，再决定是否进入 S3。

### 什么算过关（G2）

| 检查 | 判据 |
|---|---|
| 一一对应 | 每条提示词都有镜号，没有多出来的段 |
| 时长闭合 | 各段合计与分镜总时长差 ≤1 秒 |
| 引用不悬空 | 清单里出现的资产编号都在资产清单里有定义 |
| 模式唯一 | 首尾帧 或 参考图，二选一；文生仅用于无主体镜头 |
| 真图兜底 | 参数、包装、logo 镜头标明「必须用真实图」 |
| **台词在位** | 有台词的段都有台词/声音区块，且台词、说话人与分镜 `dialogue` 逐字一致 |
| 画面字段 | 每段有结构化“画面字段”表，写明主体、状态、动作、环境、光线、景别、机位/角度、运镜和依赖/可见事实；不适用项有原因 |
| 依赖传递 | 分镜关键可见事实和前置依赖已映射至首帧或段内动作 |

### 交接卡（S2 → S3）

```
任务：段号 + 时长 + 模式 + 参考图编号 + 提示词 + 候选数
台词：每段原文是否已写入提示词（逐字一致）
资产：每张图的状态（已有 / 待生成 / 待拍摄）
工具：用哪个模型、什么分辨率、什么画幅、音频必须开
顺序：先出资产图，再出首帧，最后出片段
```

### 容易卡在哪

- 资产没编号，同一只产品在清单里出现三种叫法 → 先统一编号
- 一段 12 秒还想一次生成 → 切成两段，写清交接帧
- 想同时用首帧和参考图 → 模型侧互斥，选一个

## S3 · 生成

### 进来要有什么

`02-资产清单.md`、`03-生成清单.md`，且 G2 已过。

进入 S3 前运行 `check_sequence.py --enter S3`。不得以素材已经存在为由跳过 S1A、S1B 或 S2。

### 做什么

S3 分两小段，**先图后片**：

```
3a 资产准备（交给 short-video-assets）
   资产图 → 首帧，按编号落盘，过验收
3b 片段生成（交给 short-video-generate）
   按生成清单建任务，逐段出 2–4 个候选，过媒体体检 + 抽帧质检
```

顺序不能倒。没有资产图就直接生成片段，第 3 段开始主体就会变样。

本技能在这一段只做两件事：把清单交给资产层、按 G3 收素材。**资产怎么出、片段怎么跑、怎么验，都不在这里写。**

### 出什么

```
04-素材/
├── 00-工单.md          资产生产工单（assets 层写）
├── 00-生成台账.md      片段任务与状态（generate 层写）
├── 01-资产图/    PR-01_产品主图_v1.png
├── 02-首帧/      S01_f01_v1.jpg
└── 03-片段/      S01_v1.mp4、S01_v2.mp4
```

命名规则：

| 类型 | 格式 | 谁负责 |
|---|---|---|
| 资产图 | `<编号>_<用途>_v<N>.<ext>` | `short-video-assets` |
| 首帧 | `S<段号两位>_f01_v<N>.jpg` | `short-video-assets` |
| 片段 | `S<段号两位>_v<N>.mp4` | `short-video-generate` |

**永不覆盖旧版本。** 选错了还能退回去。

资产图、首帧和视频候选完成后，在对话中直接呈现每个编号/段号的候选版本、推荐版本、可用性与失败原因。候选图、首帧和片段可以提供可打开链接或附件，但不能只给台账或素材目录。

### 什么算过关（G3）

| 检查 | 判据 |
|---|---|
| 齐 | 每段都有可用版本，缺的写进阻塞项 |
| 检 | 每段都过了媒体体检（文件、时长、比例、音轨符合提交参数） |
| 像 | 产品不变形、标签可读不改字 |
| 接 | 相邻段同一产品、同一光线方向、同一画幅 |
| 定 | 多候选时已选定并写进清单 |
| 角色识别点 | 对照 `adaptation.md` 的 `visual_anchor` 和角色清单，逐镜核对标志性特征及数量 |
| 跨段因果与道具 | 用项目清单逐项核对前提出现顺序、指认对象是否在场、道具形制及归属；案例脚本中的固定镜号与颜色阈值不可直接移植 |
| 台词定案 | 听核定版片段并记录在 04-素材/00-台词定案.json；含糊处可用多次转写辅助，但须人工终审 |
| 全片 | 已按时间顺序人工审看定版片段，跨段因果、角色/道具状态、空间和节奏均有结论；问题已退回或记录为接受 |
| 节奏预检 | S3 用定版片段的台词时间轴或临时字幕预检；尚无成片字幕时记录「待 S4 实测」，不虚报已测 |
| 后期计划 | 生成清单承诺的拟音/叠字等后期项均有 S4 执行计划，无悬空承诺 |

「像」和「接」是抽帧看出来的，「检」是脚本跑出来的。两个都过才能算通过——**下载完成不等于可用**。

生成前审首帧故事板，确认空间、角色、证据和状态是否铺设；生成后仍须按时间顺序审看全片素材，确认动作、声音和跨段节奏。首帧故事板不替代动态审片。

### 交接卡（S3 → S4）

```
素材清单：定版映射文件 / 段号 / 实际时长 / 是否可用
缺口：哪段没有可用版本，什么原因
台词：每段是否已逐句听核，有无漏句或念错
全片审看：结论 / 跨段问题 / 是否退回
后期项：已完成 / 待完成 / 豁免及确认人
声音：BGM 是否已选
```

### 容易卡在哪

- 一段抽十几次都不对 → 问题多半在首帧或参考图，不在提示词
- 产品变形反复出现 → 该镜改成真实图打底 + 局部生成
- 段与段之间色调不一致 → 补一条统一的风格锚，重抽受影响段
- 同一段被提交了两次 → 没读台账，先查状态再动手，重复提交会拿到两个版本
- 台词总是漏后半句 → 字数超了，砍到 40 字以内或拆段

## S4 · 交付

### 进来要有什么

`04-素材/` 齐，每段台词已听核过，BGM 已选，且 G3 已过。

进入 S4 前运行 `check_sequence.py --enter S4`。

**没有配音环节。** 人物对白与旁白已经在 S3 由模型生成，S4 只需要听核、配乐与混音。

### 做什么

按顺序五步，每步单独过一遍：

1. **粗剪对位** —— 按段号与镜号顺序拼，先不管节奏
2. **节奏修剪** —— 掐掉每段尾巴的废帧，切点落在动作完成处
3. **字幕** —— 以实际听到的台词为准逐句上，不按语音识别硬对齐
4. **混音** —— 人声打底，BGM 压到不盖字
5. **导出** —— 按平台规格导出，命名带版本

### 出什么

```
05-成片/
├── 成片-v1.mp4
└── 封面-v1.jpg
```

交付时直接向用户贴出成片摘要和可打开链接：实际时长、画幅、分辨率、字幕/人声结论、BGM、最长无台词区间、已知残余问题，以及封面。不能只回复“成片在 05-成片”。

### 什么算过关（G4）

| 检查 | 判据 |
|---|---|
| 时长 | 与目标偏差 ≤10% |
| 字幕 | **与实际听到的台词逐句一致**，无错字、无错行 |
| 声音 | 人声清楚，BGM 不压人声 |
| 规格 | 画幅、分辨率、帧率符合目标平台 |
| 节奏对账 | 最长无台词区间符合验收画像；允许长静默的区间有分镜承载说明和交付定位 |
| 节奏实测 | 运行本技能 scripts/check_rhythm.py --srt <成片字幕.srt> --dur <成片秒数>，把报告及听核判断附在 00-流程状态.md；字幕空档只是无台词代理指标 |
| 后期闭环 | 生成清单承诺的后期项均已完成并引用产物，或有验收人确认的豁免 |

### 交接卡（S4 → S5）

```
成片：文件名、实际时长、画幅
封面：文件或待做
卖点：这一条最想让人记住的一句
素材授权：哪些画面涉及他人肖像或场地
```

### 容易卡在哪

- 分段生成的东西拼起来节奏碎 → 别用转场掩盖，重切尾巴
- 字幕跟着语音识别跑 → 以听核后的定版音轨为准，短剧脚本、结构化分镜中的对白和识别结果用于核对
- 导出后发现画幅不对 → 剪辑序列一开始就按目标平台设

## S5 · 发布

### 进来要有什么

`05-成片/` 的成片，且 G4 已过。

进入 S5 前运行 `check_sequence.py --enter S5`。

### 做什么

填 `06-发布包.md`，六件套：标题、封面文案、正文、话题、发布时间、AI 标识。规范见 `delivery-and-publish.md`。

### 出什么

`06-发布包.md`（模板见 `assets/publish-pack-template.md`）。

完整的发布包必须同时直接显示在对话里：3 个标题候选与推荐、封面文案、正文前两行、完整正文、3–5 个话题、建议发布时间、AI 标识、合规结论。文件路径只能作为附带记录，不能代替用户可见的发布方案。

### 什么算过关（G5）

| 检查 | 判据 |
|---|---|
| 合规 | 强监管类目已另行审核，无绝对化用语、无未证实功效 |
| 标识 | AI 生成内容按平台要求标注 |
| 齐备 | 标题、封面、话题、时间都有 |
| 干净 | 无个人信息、无未授权肖像与场地 |

### 收尾
