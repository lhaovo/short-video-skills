# 生成台账与状态机

台账是 `04-素材/00-生成台账.md`。它的第一作用不是留档，是**防重复提交**。

同一段分两次提交，不只是浪费额度，还会拿到两个不同版本，剪辑时不知道该用哪个。

## 一、每段必须记的字段

```markdown
### S01

- 请求指纹：a9a27e7f6433
- 模式：首帧图生
- 首帧：04-素材/02-首帧/S01_f01_v1.png
- taskId：abc123
- KIE 状态：generating
- 状态：生成中
- 输出文件：04-素材/03-片段/S01_v1.mp4
- 失败阶段：无
- 失败原因：
- 更新时间：2026-10-22 15:40
```

**请求指纹**由模型、提示词、模式、时长、比例、分辨率、音频开关算出来，脚本自动给出。指纹变了说明这是一个新请求，旧的记录作废；指纹没变就说明是同一件事，不该再提交。

**不要记 API key，不要记临时 URL。** 前者是密钥，后者会过期且没有追溯价值。

## 二、状态只有九个

| 状态 | 含义 | 允许的下一步 |
|---|---|---|
| 待生成 | 还没有 taskId | 可以提交 |
| 待确认重新生成 | 想重做，但用户没点头 | **等**，不提交 |
| 等待中 | waiting / queuing | 只查询同一 taskId |
| 生成中 | generating | 只查询同一 taskId |
| 生成成功，待下载 | success | 只下载 |
| 下载完成，待质检 | 本地有文件、非空 | 跑体检 + 抽帧 |
| 下载完成，质量通过 | 体检过 + 人看过 | **跳过** |
| 质量失败 | 人判不能用 | 记录原因，等确认后重做 |
| 失败 | fail 或不可恢复错误 | 记录，**不自动重提** |

## 三、防重复提交：按顺序判

每次动手之前，先过这六条，从第一条开始匹配，命中就停：

1. 状态是「质量通过」且文件存在非空 → **跳过**
2. 有 taskId 且状态是「等待中 / 生成中」→ **只查询**，不新建
3. 有 taskId 且状态是「生成成功，待下载」→ **只下载**；URL 过期就查同一 taskId 换地址
4. 状态是「失败」→ 保留 taskId 和原始错误，**不自动重提**
5. 状态是「待确认重新生成」→ **等用户确认**
6. 状态是「待生成」且没 taskId、指纹已写 → **可以提交**

## 四、什么时候才允许新建任务

必须同时满足：

- 用户明确说「重做」「重新生成」，或确认了变更后的指纹
- 台账里已写下旧 taskId 和旧指纹（不能假装旧任务不存在）
- 状态已改回「待生成」，taskId 字段已清空

新建后立刻写入新 taskId、新指纹、状态「等待中」、更新时间。**先记录，再做别的。**

## 五、失败阶段分四种

失败要分清是哪一步坏的，因为修法完全不同：

| 失败阶段 | 表现 | 只能做什么 |
|---|---|---|
| 提交 | createTask 报错 | 改参数后重新提交 |
| 查询 | 网络错误、查不到 | 保留上次状态，稍后重查，**不能据此重提** |
| 结果解析 | success 但拿不到 URL | 查同一 taskId，**不能重提** |
| 下载 | 403 / 404 / 网络断 | 查同一 taskId 换新 URL 再下，**不能重提** |

后三种都不是"生成失败"，重提只会浪费额度并丢掉已经生成好的结果。

## 六、并发跑的时候，台账怎么写

批量默认 5 路并发。这带来一个必须提前想清楚的问题：**五段同时结束，五次写入会互相覆盖。**

如果每段一完成就去改 `00-生成台账.md`，后写的会盖掉先写的，最后台账里只剩一段记录——而另外四段其实已经生成了，只是账上没记。下一次续做时，它们会被判成"待生成"，全部重跑。

### 正确做法：先跑完，再一次性回写

```
① 批量跑完，收下脚本输出的 items
② 按段号一次性补齐台账（五段一起写）
③ 写完对着清单核：清单 N 段，台账必须 N 行
```

脚本输出的 `items` 已经**按任务表顺序排好**，不是按完成顺序。所以你可以直接照着往下写，不用重新排序。

每行要有的：段号、请求指纹、taskId、状态、输出文件。失败的那几段照实写失败阶段和原因。

### 另一种做法：串行 + 边跑边记

把 `--concurrency` 设成 1，就是逐段跑，跑一段写一段。慢，但不会有覆盖问题，而且失败了能立刻看到。

**这两种只能选一种。** 「并发 + 零散写」是最坏的组合：又慢又不准，还查不出错在哪。

### 加锁不管用

有人会想到"写文件时加锁"。这里不适用——因为写台账的是你（或 AI）在对话里改文件，不是脚本里的线程。**并发的是脚本，写账的是人，两者不同步。** 只能靠"跑完再一次性写"这个流程来保证。

### 一个自查

并发跑完后，问自己三句话：

1. 脚本汇总里 `ok + failed` 是不是等于清单段数？
2. 台账行数是不是等于清单段数？
3. 每行的 taskId 是不是都不一样？

三个都"是"才对。第三个尤其要看——taskId 重复说明有段被提交了两次。

## 七、续做怎么接上

隔一天或换人接手时，只读台账，不从头猜：

1. 打开 `04-素材/00-生成台账.md`
2. 扫状态列，找出不是「质量通过」的段
3. 对每一段按第三节判该做什么
4. 汇报三行：已完成几段 / 卡在哪段 / 下一步做什么

不要按「本地有没有 mp4 文件」来判断进度。文件可能在，但没体检过；也可能体检过了，但画面不能用。
