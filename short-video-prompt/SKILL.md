# 视频提示词台

一张给人看的分镜表，和一条能跑通的生成清单，中间隔着一层翻译。这个技能就做这层翻译。

产出两份文件：**资产清单**（要准备哪些图）和**生成清单**（每一段怎么生）。

它不重新选题、不改剧本结构、不判定内容好坏——那是上游的事。它也不直接出图出片，只把话说到可以直接执行。

---

## 一、五条铁律

写在最前面，因为每一条都对应一类翻车。

1. **资产先行。** 没编号不许写提示词。同一只产品在第 3 段变成另一只，根因几乎都是没建资产。
2. **一条视频提示词只描述一个连续时刻。** 场景一换就分段，别让模型自己转场。
3. **主体用 anchor phrase 逐字复用。** 换近义词等于换人。
4. **产品来源先定，再写词。** 有实拍或官方素材就优先用；没有也可以 AI 生成，但要把几何、印刷、logo 写死。**有参数或功效宣称的镜头，只能用实拍或官方素材。**
5. **视频提示词正向写，图像提示词才用负向段。** 这两套语法不能互相搬运，见 `references/prompt-syntax.md` 第八节。

---

## 二、输入

### 必需

| 项 | 从哪来 | 缺了怎么办 |
|---|---|---|
| 分镜表 | 常见为策划案第四节，五列 | 没有镜号或时长，**拒收**，不猜 |
| 产品真名与规格 | 策划案第一节 | 没有就问，问不到就先标「待确认」 |
| 目标模型 | 用户指定，默认 Seedance | 默认即可，不必追问 |

分镜表五列：镜号 / 时长 / 这一镜讲什么 / 口播 / 屏幕文字。

### 可选

- 画幅（默认 9:16）、视频分辨率（默认 720p，与生成端一致）
- 单段时长上下限（默认 5–10 秒）
- 是否要音频（**必须开**。旁白由模型直接念，关掉等于没有声音；只有确认为空镜时才关）

### 两种入口

| 入口 | 处理 |
|---|---|
| 标准入口 | 读策划案第四节，字段齐全，直接进第三步 |
| 宽松入口 | 只有一份外部 markdown 表，先解析，**回显给用户核对**，缺字段标出来 |

宽松解析要显式告知「这是降级解析，请核对」。无声出错比报错更麻烦。

## 三、八步

```
1 读表 → 2 画面化 → 3 提资产 → 4 切段 → 5 首帧 → 6 组词 → 7 出清单 → 8 自检
```

### 第 1 步 · 读表

把五列读成结构，顺带记住产品信息。这一步只做体检，不创作。

体检三条：

- 镜号连续、时长为正
- 每镜时长 2–6 秒（越界的标出来）
- 分镜表里有「这一镜讲什么」，不是只有口播

### 第 2 步 · 画面化

**这是整个技能里唯一的创作步骤，也是最容易被跳过的一步。**

分镜表给的是内容描述（「解释为什么外面烫里面凉」），提示词要的是画面。中间必须补六项：

| 项 | 问什么 | 例 |
|---|---|---|
| 主体 | 画面里有什么 | 白色陶瓷饭盒、掀开的盖子 |
| 动作 | 谁在做什么，一个动作 | 勺子从中心插进去 |
| 环境 | 在哪，周围有什么 | 办公桌、微波炉在背景 |
| 光线 | 光从哪来、什么色温 | 顶部暖白光，左窗补光 |
| 景别 | 多远 | 特写 |
| 运镜 | 怎么动（只选一种） | 固定机位，缓慢推近 |

**六项缺一不可。** 缺项时先自己补，补不出来就问用户一句——不要空着写进提示词，空着的地方模型一定会自己编。

### 第 3 步 · 提资产

按 `references/assets.md` 做四件事：编号、拆分、定来源、出总表。

- 编号前缀：`PR` 产品 / `SC` 场景 / `CH` 人物 / `SP` 道具
- 进清单的判据：**被两段以上引用，或要求身份一致**
- 来源三档：**实拍 / 官方素材**（有就用）、**AI 生成**（没有实拍时用，锁几何与印刷）、**待补**

### 第 4 步 · 切段

按三条约束取交集：

1. **段时长 ≥ 这段台词字数 ÷ 4 字/秒**（模型念中文约 4–5 字/秒，按低的算）
2. 单段 5–10 秒（模型上限见 `prompt-syntax.md`）
3. 一个动作一段

第 1 条用 4 而不是 6.5，是有原因的：**模型念台词不会加快语速，它直接漏掉后半句。** 按乐观语速切出来的段，生成出来就是缺句子，比多切一段麻烦得多。

单段台词**上限 36 字**。超了拆段，不要压字数硬塞。

超长镜用**延展 + 交接帧**：写清上一段尾帧是什么画面状态，不是写「承接上一段」。

### 第 5 步 · 首帧

不是每段都要首帧。按敏感度判断：

| 必须出首帧 | 可以直接文生视频 |
|---|---|
| 产品特写、手持动作、出现 logo 或文字 | 空镜、氛围、转场、纯光效 |

首帧图用**图像提示词**写（见 `assets.md` 第四节七模块），原则是「真实产品打底 + AI 生成场景」。

### 第 6 步 · 组词

按 `references/prompt-syntax.md` 的六区块写：

```
[风格画幅] → [素材引用] → [锁定主体] → [时间轴] → [旁白·声音] → [质量约束]
```

四个必须写进去的：单一运镜、`Motion:` 清单、**台词原文（照稿念，不改字）**、`No subtitles`。

第五个区块现在承载的是**旁白本身**——不再有独立配音环节，台词就靠这一段交给模型。分镜表的口播列要**逐字搬进来**，不加语气标注、不加括号补充、不改一个词。改了字幕就对不上音。

### 第 7 步 · 出清单

填两份模板，落到上游指定的目录（默认 `02-资产清单.md`、`03-生成清单.md`）。

### 第 8 步 · 自检

跑六条，能跑脚本的跑脚本：

```bash
python scripts/check_gen_list.py --dir <制作目录>
```

退出码：`0` 通过 / `2` 有致命项 / `3` 文件读不了。

## 四、两份产物

### 资产清单（`02-资产清单.md`）

表格六列，后面逐条附图像提示词：

| 编号 | 类型 | 用途 | 来源 | 被哪些段引用 | 状态 |
|---|---|---|---|---|---|

- 类型：产品主体 / 产品细节 / 场景 / 人物 / 道具
- 来源：实拍或官方素材 / AI 生成 / 待补
- 状态：已有 / 待出图 / 待拍

### 生成清单（`03-生成清单.md`）

**一张概览表 + 逐段提示词全文**（提示词太长，塞进表格会看不清）：

| 段号 | 镜号 | 时长 | 模式 | 引用素材 | 首帧 | 后期项 | 候选数 |
|---|---|---|---:|---|---|---|---:|

- 模式：首尾帧 / 参考图 / 文生
- 首帧：`S01_f01` 或「无」
- 候选数：建议 2–4

**模式的三种写法是给下游做选择用的，不是所有模型都支持。** 当前 KIE Seedance 只开文生、首帧、首尾帧三种，参考图模式要降级成首帧——降级规则在 `short-video-generate` 里，本技能照写即可，不用迁就模型改口径。

表下按 `### S01 · 镜 1–2 ｜ 8s ｜ 首尾帧` 逐段给出六区块完整提示词，并附首帧来源与后期项。

模板见 `assets/`。

## 五、自检七条

| # | 检查 | 不过怎么办 |
|---|---|---|
| 1 | 每段都有镜号，没有多出来的段 | 回第 4 步重切 |
| 2 | 各段时长合计与分镜总时长差 ≤1 秒 | 调段长，不改分镜 |
| 3 | 清单里引用的资产编号都在资产清单里有定义 | 补定义或删引用 |
| 4 | 主模式唯一：首尾帧 与 参考图 不混用 | 全片统一 |
| 5 | 产品镜头来源已标明；有宣称的镜头用了实拍或官方素材 | 回第 3 步改来源 |
| 6 | 每条视频提示词都有：单一运镜、`Motion:`、`No subtitles` | 逐条补 |
| 7 | **有台词的段，旁白区块与分镜口播逐字一致** | 逐段比对，错一个字也要改 |

第 4 条的准确口径：**首尾帧与参考图互斥，文生只用于无主体镜头。** 产品镜头混用两种主模式，出来的东西接不上。

第 7 条是这次新增的，也是最容易漏的一条。做法很笨但有效：**把分镜表的口播列和清单里的旁白区块并排放，逐字对一遍。** 改了一个标点、换了一个同义词，字幕就要跟着改，而字幕在 S4 才做——那时发现已经晚了。

顺手检查两件事：每段台词是否超过 36 字（超了模型会漏念）、有没有混进 `（笑）`「[兴奋]」这类语气标注（模型会念出来）。

## 六、边界

- **不重新编排内容**：镜号、顺序、时长来自上游，本技能不改结构
- **不判定内容好坏**：选题、钩子、结构是否成立，属于上游
- **不直接生成**：只出清单与提示词，出图交给 `short-video-assets`、出片交给 `short-video-generate`
- **不承诺一次成功**：生成是概率的，本技能只保证「值得抽的那一条」概率更高
- **不做参数搬家**：模型参数会变，技能里给的是原则与通用口径，具体数值以官方文档为准
