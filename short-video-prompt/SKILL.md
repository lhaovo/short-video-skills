# 视频提示词台

一份给人看的短剧分镜，和一条能跑通的生成清单，中间隔着一层翻译。这个技能就做这层翻译。

产出两份文件：**资产清单**（要准备哪些图）和**生成清单**（每一段怎么生）。

它不改故事、不重写剧情、不判定内容和分镜好坏——那是上游的事。它也不直接出图出片，只把话说到可以直接执行。

---

## 一、五条铁律

写在最前面，因为每一条都对应一类翻车。

1. **资产先行。** 没编号不许写提示词。同一只产品在第 3 段变成另一只，根因几乎都是没建资产。
2. **一条视频提示词只描述一个连续时刻。** 场景一换就分段，别让模型自己转场。
3. **主体用 anchor phrase 逐字复用。** 换近义词等于换人。
4. **产品来源先定，再写词。** 有实拍或官方素材就优先用；没有也可以 AI 生成，但要把几何、印刷、logo 写死。**有参数或功效宣称的镜头，只能用实拍或官方素材。**
5. **视频提示词正向写，图像提示词才用负向段。** 这两套语法不能互相搬运，见 `references/prompt-syntax.md` 第八节。

## 二、输入

### 顺序门

在 `short-video-flow` 管理的制作目录中，开始 S2 前必须运行：

```bash
python short-video-flow/scripts/check_sequence.py --dir <制作目录> --enter S2
```

只有 G1-A、G1-B 均为「已批准」且退出码为 `0` 才能继续。即使手上已有分镜、资产或提示词，也不能跳过 S1A/S1B 直接写生成清单。检查失败时回到总控报告阻塞项。

### 必需

| 项 | 从哪来 | 缺了怎么办 |
|---|---|---|
| 短剧分镜 | `01-故事/drama/storyboard.md` 与当前集 `storyboards/NN.json` | 没有镜号、数值时长、动作或对白，**拒收**，不猜 |
| 脚本与改编契约 | 当前集 `scripts/NN.md`、`adaptation.md` | 缺少角色、地点、必须保留事实时退回 S1B |
| 关键实体与规格 | 改编契约、脚本或用户补充 | 有产品/道具真名、型号或参数时必须确认；没有就问 |
| 目标模型 | 用户指定，默认 Seedance | 默认即可，不必追问 |

优先读取结构化 JSON；`storyboard.md` 用于快速审阅与人工核对。每个镜头的 `order`、`duration_sec`、`action`、`dialogue`、`character_refs`、`shot_size`、`camera_move`、`location`、`visual_prompt` 是翻译输入。提示词层可据此补全观众认知、前置依赖、关键可见事实和时长意图，但不得改动剧情、动作结果或对白。

### 可选

- 画幅（默认 9:16）、视频分辨率（默认 480p，与生成端一致）
- 单段时长上下限（默认 5–10 秒）
- 是否要音频（**必须开**。人物对白与环境音由模型直接生成，关掉等于没有声音；只有确认为纯视觉空镜时才关）

### 两种入口

| 入口 | 处理 |
|---|---|
| 标准入口 | 读 `storyboards/NN.json`、`storyboard.md`、当前集脚本与 `adaptation.md`，字段齐全，直接进第三步 |
| 宽松入口 | 只有一份外部 markdown 分镜，先解析，**回显给用户核对**，缺字段标出来；不得从小说原文自行重编分镜 |

宽松解析要显式告知「这是降级解析，请核对」。无声出错比报错更麻烦。

## 三、八步

```
1 读表 → 2 画面化 → 3 提资产 → 4 切段 → 5 首帧 → 6 组词 → 7 出清单 → 8 自检
```

### 第 1 步 · 读表

把结构化分镜、可读分镜和脚本按镜号对应，记住角色视觉锚点、地点、道具与必须保留事实。这一步只做体检，不创作。若短剧分镜技能已安装，运行其 `drama_state.py status`、`check-source` 与 `validate`；独立安装本技能时按结构化分镜字段逐镜核对，并要求上游补齐后再继续。

体检三条：

- 镜号连续、时长为正
- 每个镜头的 `action`、`location`、`shot_size`、`camera_move` 非空；无对白时 `dialogue` 为空是合法值
- 所有 `character_refs` 都能在 `adaptation.md` 的角色清单中找到
- 分镜里有关键动作与可见结果，不只有对白

### 第 2 步 · 画面化

**这是整个技能里唯一的创作步骤，也是最容易被跳过的一步。**

短剧分镜给的是动作、情绪与叙事功能，提示词要的是可逐帧执行的画面。每段必须补齐下列字段：

| 项 | 问什么 | 例 |
|---|---|---|
| 主体 | 画面里有什么 | 白色陶瓷饭盒、掀开的盖子 |
| 状态 | 主体当前是什么状态 | 盖子打开，饭盒放在桌面 |
| 动作 | 谁在做什么，一个动作 | 勺子从中心插进去 |
| 环境 | 在哪，周围有什么 | 办公桌、微波炉在背景 |
| 光线 | 光从哪来、什么色温 | 顶部暖白光，左窗补光 |
| 景别 | 画面取多大范围 | 特写 |
| 机位/角度 | 相机在主体的什么位置 | 桌面高度，侧前方 30 度 |
| 运镜 | 怎么动（只选一种） | 固定机位，缓慢推近 |

**字段缺一不可。** 每段清单必须显式写出主体、状态、动作、环境、光线、景别、机位/角度和运镜；明确不适用时写原因。缺项时先自己补，补不出来就问用户一句——不要空着写进提示词，空着的地方模型一定会自己编。

分镜中的“关键可见事实”和“前置依赖”必须在生成清单中标明落点：是首帧的可见状态，还是视频段内发生的动作。过程型动作不能要求一张首帧同时表现前、中、后。

### 第 3 步 · 提资产

按 `references/assets.md` 做四件事：编号、拆分、定来源、出总表。

- 编号前缀：`PR` 产品 / `SC` 场景 / `CH` 人物 / `SP` 道具
- 进清单的判据：**被两段以上引用，或要求身份一致**
- 来源三档：**实拍 / 官方素材**（有就用）、**AI 生成**（没有实拍时用，锁几何与印刷）、**待补**

### 第 4 步 · 切段

按三条约束取交集：

1. **段时长 ≥ 这段台词字数 ÷ 4 字/秒**（模型念中文约 4–5 字/秒，按低的算）
2. 单段 5–10 秒（模型上限见 `prompt-syntax.md`）
3. 一个动作一段；不同说话人的连续对白若模型容易串角色，按说话人和反打关系拆段

第 1 条用 4 而不是 6.5，是有原因的：**模型念台词不会加快语速，它直接漏掉后半句。** 按乐观语速切出来的段，生成出来就是缺句子，比多切一段麻烦得多。

单段台词**上限 36 字**。同一说话人连续台词超限就拆段；多人交叉对白按说话人与反应镜头拆，不要把整场对话塞进一个生成任务。

超长镜用**延展 + 交接帧**：写清上一段尾帧是什么画面状态，不是写「承接上一段」。

### 第 5 步 · 首帧

不是每段都要首帧。按敏感度判断：

| 必须出首帧 | 可以直接文生视频 |
|---|---|
| 产品特写、手持动作、出现 logo 或文字 | 空镜、氛围、转场、纯光效 |

首帧图用**图像提示词**写（见 `assets.md` 第四节七模块），原则是「真实产品打底 + AI 生成场景」。

### 第 6 步 · 组词

按 `references/prompt-syntax.md` 的六区块写：

```
[风格画幅] → [素材引用] → [锁定主体] → [时间轴] → [台词·声音] → [质量约束]
```

四个必须写进去的：单一运镜、`Motion:` 清单、**台词原文（照稿念，不改字）**、`No subtitles`。

第五个区块现在承载的是**人物对白或旁白本身**——不再有独立配音环节，台词就靠这一段交给模型。分镜的 `dialogue` 字段要**保留说话人和原文**，不加语气标注、不加括号补充、不改一个词。改了字幕就对不上音。

### 第 7 步 · 出清单

填两份模板，落到上游指定的目录（默认 `02-资产清单.md`、`03-生成清单.md`）。随后必须在对话中直接呈现：

1. 资产清单总表；
2. 生成清单逐段概览表；
3. 每段完整视频提示词；
4. 候选数、预计生成段数和成本/时长风险；
5. 仍需用户确认的关键实体、真实素材或视觉选择。

不能只回复“清单已生成，请查看文件”。落盘文件是正式执行版本，对话展示是用户审阅版本，两者必须一致。清单内容较长时，先给结论摘要，再按 S01、S02 顺序完整展开。

展示完成后，把 G2 的 `门禁状态` 写成「等待用户确认」，记录待批准版本，然后结束当前回合。只有用户明确确认清单和本轮生成预算后，才能把 G2 改成「已批准」并把控制权交回 `short-video-flow`。`继续吧` 不等于授权付费生成。

本技能只完成 S2，不直接进入素材或视频生成。

### 第 8 步 · 自检

跑六条，能跑脚本的跑脚本：

```bash
python scripts/check_gen_list.py --dir <制作目录>
```

退出码：`0` 通过 / `2` 有致命项 / `3` 文件读不了。

## 四、两份产物

### 资产清单（`02-资产清单.md`）

表格六列，后面逐条附图像提示词：

| 编号 | 类型 | 用途 | 来源 | 被哪些段引用 | 状态 |
|---|---|---|---|---|---|

- 类型：产品主体 / 产品细节 / 场景 / 人物 / 道具
- 来源：实拍或官方素材 / AI 生成 / 待补
- 状态：已有 / 待出图 / 待拍

### 生成清单（`03-生成清单.md`）

**一张概览表 + 逐段提示词全文**（提示词太长，塞进表格会看不清）：

| 段号 | 镜号 | 时长 | 模式 | 引用素材 | 首帧 | 后期项 | 候选数 | 前置依赖/关键事实 |
|---|---|---|---:|---|---|---|---:|---|

- 模式：首尾帧 / 参考图 / 文生
- 首帧：`S01_f01` 或「无」
- 候选数：建议 2–4

**模式的三种写法是给下游做选择用的，不是所有模型都支持。** 当前 KIE Seedance 只开文生、首帧、首尾帧三种，参考图模式要降级成首帧——降级规则在 `short-video-generate` 里，本技能照写即可，不用迁就模型改口径。

表下按 `### S01 · 镜 1–2 ｜ 8s ｜ 首尾帧` 逐段给出八个画面字段与完整提示词，并附首帧来源、前置依赖和后期项。

模板见 `assets/`。

## 五、自检九条

| # | 检查 | 不过怎么办 |
|---|---|---|
| 1 | 每段都有镜号，没有多出来的段 | 回第 4 步重切 |
| 2 | 各段时长合计与分镜总时长差 ≤1 秒 | 调段长，不改分镜 |
| 3 | 清单里引用的资产编号都在资产清单里有定义 | 补定义或删引用 |
| 4 | 主模式唯一：首尾帧 与 参考图 不混用 | 全片统一 |
| 5 | 产品镜头来源已标明；有宣称的镜头用了实拍或官方素材 | 回第 3 步改来源 |
| 6 | 每条视频提示词都有：单一运镜、`Motion:`、`No subtitles` | 逐条补 |
| 7 | **有台词的段，台词/声音区块与分镜 `dialogue` 逐字一致且说话人正确** | 逐段比对，错一个字也要改 |
| 8 | 画面字段齐全 | F7 只检查段内“画面字段”表是否存在、字段齐全且有值，不从散文关键词推断；主体、状态、动作、环境、光线、景别、机位/角度、运镜、依赖/可见事实均须填写，不适用项说明原因 |
| 9 | 依赖已传递 | 分镜前置依赖和关键可见事实已映射到首帧或段内动作 |

检查器 F8 只确认概览表逐段填写了“前置依赖/关键事实”，不能证明内容真的被首帧或段内动作呈现；G2 仍需人工逐段核对映射。

第 4 条的准确口径：**首尾帧与参考图互斥，文生只用于无主体镜头。** 产品镜头混用两种主模式，出来的东西接不上。

第 7 条是最容易漏的一条。做法很笨但有效：**把结构化分镜的 `dialogue` 和清单里的台词/声音区块并排放，逐字对一遍。** 改了一个标点、换了一个同义词，字幕就要跟着改，而字幕在 S4 才做——那时发现已经晚了。

顺手检查三件事：每段台词是否超过 36 字（超了模型会漏念）、有没有混进 `（笑）`「[兴奋]」这类语气标注（模型会念出来）、多人对白是否明确标了说话人并已按反应镜头拆开。

## 六、边界

- **不重新编排内容**：镜号、顺序、时长、动作和对白来自上游，本技能不改剧情与结构
- **不判定内容好坏**：故事、钩子、改编与分镜是否成立，属于上游
- **不直接生成**：只出清单与提示词，出图交给 `short-video-assets`、出片交给 `short-video-generate`
- **不承诺一次成功**：生成是概率的，本技能只保证「值得抽的那一条」概率更高
- **不做参数搬家**：模型参数会变，技能里给的是原则与通用口径，具体数值以官方文档为准
