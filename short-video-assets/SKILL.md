# 资产准备台

视频生成能不能接得上，取决于这一步。**要解决的问题只有一个：让同一样东西在每一张图里都是同一样东西。**

输入是资产清单（或分镜表），输出是一批按编号命名、可直接被 `short-video-generate` 当首帧引用的图。

它不写分镜、不切段、不写视频提示词，也不生成视频。它负责「图」这一段。

---

## 零、顺序门

在 `short-video-flow` 管理下进入 S3 前必须运行：

```bash
python short-video-flow/scripts/check_sequence.py --dir <制作目录> --enter S3
```

只有 G1-A、G1-B、G2 均为「已批准」且退出码为 `0` 才能出图。已有产品图、角色图或首帧不能成为跳过 S1A、S1B、S2 的理由；它们只能作为本轮资产生产的上游参考。检查失败时停止并交回总控。

G2 必须是「已批准」，并且批准范围明确包含本轮资产图生成预算。只是技术检查通过、G2 仍为「等待用户确认」时，不得提交付费生图任务。

---

## 一、四条铁律

1. **先锚点，后派生。** 母版没定，不要做角度图。角度图是照着母版长出来的，母版错了全组都错。
2. **一次只改一个变量。** 换角度就不换光，换光就不换角度。两个一起改，出问题分不清是谁的错。
3. **一次只生成一版。** 每个资产编号先只提交一张。验收失败后再生成 `v2`，不得预先批量生成多张候选。失败旧版可保留追溯，但不作为并行候选。
4. **图和清单必须对得上。** 编号就是文件名。清单里有 `PR-01`，目录里就得有 `PR-01_*`。

---

## 二、资产分三级

不是每张图都值得同等投入。先分级，再分配精力。

| 级别 | 是什么 | 例 | 要求 |
|---|---|---|---|
| **锚点级** | 全片身份基准，被多处引用 | 产品主图、人物三视图、主场景全景 | 最严：逐项验收，一次只生成一版 |
| **派生级** | 从锚点长出来的角度、状态、细节 | 产品背面、开盖状态、手部特写 | 必须与锚点并排比对 |
| **一次性** | 只出现一次，不影响一致性 | 空镜、光效、转场素材 | 一次生成一版，通过即可 |

**分级错了会浪费：** 把空镜当锚点做，一条 30 秒的片子会卡三天；把产品主图当一次性做，后面每段都得重来。

## 三、来源：三种都行，看用途选

| 来源 | 什么时候用 | 要注意 |
|---|---|---|
| **实拍** | 有实物、要准确、涉及参数或功效 | 最好，但要有素材 |
| **AI 生成** | 无实物、虚构场景、氛围、人手 | 要锁几何与印刷，每次只生成一版 |
| **官方素材** | 品牌方提供的主图、包装图 | 直接当锚点，最稳 |

**不强制实拍。** 纯 AI 生成的片子，整套资产都可以是 AI 出的，只要内部一致。

### 一个必须提前说清的风险

如果这条片子**要对观众宣称具体参数或功效**（容量、时长、成分、效果），而画面里的产品是 AI 生成的，那画面与宣称之间就对不上——轻则被评论区指出，重则构成虚假宣传。

处理方式只有一条：**有宣称，产品画面就用实拍或官方素材；没有宣称、纯氛围或虚构内容，AI 生成完全够用。**

这一条在开工前问一句就行，不要等成片了才发现。

### AI 生成怎么跑

用自带的 `scripts/kie_gen.py`（KIE GPT Image 2），提交、立即记录 taskId、轮询、下载、按命名落盘：

```bash
# 文生图（分辨率不写就是 1K，够用）
python scripts/kie_gen.py generate --prompt "…" --ratio 9:16 \
  --out 04-素材/01-资产图/PR-01_产品主图_v1.png

# 图生图：拿锚点当参考
python scripts/kie_gen.py generate --prompt "…" --ref PR-01_产品主图_v1.png \
  --out 04-素材/01-资产图/S01_f01_v1.png

# 批量：读 JSON 任务表（默认 5 路并发）
python scripts/kie_gen.py batch --tasks tasks.json --out-dir 04-素材/01-资产图 --dry-run
python scripts/kie_gen.py batch --tasks tasks.json --out-dir 04-素材/01-资产图

# 下载失败后重跑同一条命令：查询原 taskId，只补下载
python scripts/kie_gen.py batch --tasks tasks.json --out-dir 04-素材/01-资产图

# 已知原 taskId 时直接恢复下载
python scripts/kie_gen.py retrieve --task-id <原taskId> \
  --out 04-素材/01-资产图/PR-01_产品主图_v1.png
```

分辨率默认 **1K**：这些图最终会被视频模型重采样，源图做大了不保留细节，只增加失败率。要单独放大裁切（做封面）或做白底母版二次利用时，才加 `--resolution 2K`。

批量默认 **5 张同时跑**。出图要 10–40 秒，串行跑 6 张就是三四分钟纯等；5 并发跑 6 张，总时长约等于最慢那张加一轮。被限流（`code != 200` 或 429）就 `--concurrency 2`，**不要因为限流去改提示词**。

四条纪律：

1. **先 `--dry-run`** 看请求体，再真跑。一次批量提交二十张，参数错了就是二十次浪费
2. **密钥只走环境变量** `KIE_API_KEY`，不写进脚本、任务表、工单
3. **先出锚点、完成内部一致性检查**，再逐张派生。核心锚点不单独打断流程，统一在 G3-A 停点直接发给用户验收
4. **taskId 自动落账**：脚本在提交成功后、开始等待和下载之前写入 `04-素材/00-生图任务/`。下载失败只能按原 taskId 重查重下，不能重新提交

写法、参数限制、失败处置见 `references/ai-generation.md`。

## 四、七步流程

```
1 读清单 → 2 排顺序 → 3 定级 → 4 生成一版 → 5 验收 → 6 落盘 → 7 回写
```

### 第 1 步 · 读清单

从 `02-资产清单.md` 读编号、类型、用途、来源、引用段。

清单里没有图像提示词的，用 `references/prompt-fixups.md` 的四类骨架补写；有的直接取用，不要重写。

### 第 2 步 · 排生产顺序

```
锚点级 → 派生级 → 一次性
```

同类里再按被引用次数排，引用越多的越先做。理由：引用多的资产一旦返工，牵连的段最多。

多段复用且空间连续性重要的地点，按需拆成两层资产：

1. **空间结构母版**：无人、无动作，锁定地面/墙面材质、橱窗和建筑体块、固定背景结构、空间纵深关系，以及主光源在场景中的来源和大致方向；不锁具体机位、景别、人物和临时道具。
2. **机位子母版**：从同一空间派生实际会用到的正打全景、侧位近景、俯拍、低角度仰拍或特写等空镜。首帧从对应机位子母版派生，避免全片继承同一透视和构图。

每个空间只做实际会用到的视角，不强制固定数量。光向保持空间连续，但正午/傍晚等光照版本按剧情是否跨时段决定；基础母版避免烤入不必要的强时段特征。先把代表性机位并排验收，再批量派生首帧。

### 第 3 步 · 定级

每个编号标一个级别（锚点 / 派生 / 一次性），写进工单。这一步决定生产顺序和验收严格度。

### 第 4 步 · 生成一版

每个资产编号只提交一个任务、只生成一张图。锚点、派生和一次性都遵守这一规则。

- 第一版通过验收，直接落盘并回写。
- 第一版不合格，记录具体缺陷，只对失败项改一个变量后生成下一版。
- 不预先写 `v1`、`v2` 两个候选任务，不做同提示词批量抽图。
- 不同资产编号可以在同一批次处理，但每个编号仍然只有一个输出。

出图前先确认三件事：画幅对不对、背景对不对（白底还是场景）、有没有多余元素（文字、水印、手）。

用 AI 生成时，先 `--dry-run` 看参数，再按锚点 → 派生的顺序提交。锚点先单张生成并由 Agent 逐项检查；全部资产完成后统一在 G3-A 呈交用户，不在每张锚点后额外停一次。每个编号只能有一条任务。

正式提交前，确认 G2 已由用户批准且授权范围包含本轮图片生成。若 G2 尚未批准，直接给出本次出图摘要，把 G2 设为「等待用户确认」并结束回合，不能先提交再补确认。

提交成功后，脚本立即写任务记录，状态至少包含：

```text
submitted → generated_pending_download → downloaded_pending_qc
```

如果 SSL 握手、连接重置、URL 过期或下载校验失败：

- 任务记录已经保存原 taskId；
- 重跑相同命令只查询和下载，不再调用新建任务；
- 每次下载重试前重新查询同一 taskId，获取新的临时 URL；
- 最终仍失败时保留 `generated_pending_download`，并把原 taskId 直接告诉用户；
- 只有用户明确要求重做时才使用 `--new-attempt`。

### 第 5 步 · 验收

按 `references/acceptance.md` 的七项逐条过，七项里过六项才能留，关键项（几何、印刷）不过直接打回。

验收后在对话中直接给出这一版的文件名/可打开链接、通过或打回的具体原因。涉及产品几何、人物身份、logo 或场景连续性时，还要附上和锚点并排的展示，不能只回复“已验收”。

### 第 6 步 · 落盘

```
04-素材/01-资产图/
├── PR-01_产品主图_v1.png
├── SC-01_办公桌面_v1.png
└── CH-01_女性手部_v1.png

04-素材/00-生图任务/
├── PR-01_产品主图_v1__<请求指纹>__<路径摘要>.json
└── SC-01_办公桌面_v1__<请求指纹>__<路径摘要>.json
```

命名格式：`<编号>_<用途>_v<N>.<ext>`。编号与清单一致（状态后缀 A/B 保留），用途 2–8 字、可用下划线细分，版本递增。

任务记录保存请求指纹、taskId、状态、错误阶段和输出路径；不保存密钥和临时下载 URL。

### 第 7 步 · 回写

清单状态改成「已有 / 待补」，并在工单里记下当前采用版本。**不回写，下一步就不知道该引用哪一版。**

最后把资产总表、每个编号的采用版本和待补项直接贴回对话；文件路径作为附加入口，不作为唯一交付。

### 定版资产审阅总览

在 G3-A 停点前，把已定版资产排成一张接触印样长图，作为一次性的审阅总览：

```bash
python scripts/build_asset_contact_sheet.py \
  --project <制作目录> \
  --columns 4 \
  --expected-count 15 \
  --canvas 1580x2756 \
  --quality 92
```

- `--expected-count` 可选；只有项目需要校验“是否正好 15 项”时才传，不能写死数量。
- 不传 `--canvas` 时按实际行数动态计算高度；不传 `--columns` 时默认 4 列。
- 脚本只收录有明确定版版本和有效文件的资产，排除待补、待叠字、废弃候选、首帧和视频片段。
- 输出默认写到 `04-素材/00-审阅/定版资产总览-vN.jpg`，旁车 `.json` 记录源文件 SHA-256、尺寸、EXIF 方向和定版版本。
- 总览图不是源资产，不能放进 `01-资产图`，也不能引用到视频生成。

生成后先直接查看输出像素，再把图片和定版摘要直接发给用户。**总览只能用于一次看完资产全貌；产品 logo、角色识别点等关键细节仍要打开原图确认。**

完成资产图、空间母版和首帧后，把采用版本、并排比对、失败下载和待补项直接发给用户。将 `G3-A` 门禁状态设为「等待用户确认」，结束回合。用户批准并明确授权视频生成预算后，才可把 G3-A 改为「已批准」并交回总控。

## 五、一致性怎么保

同一编号的历史版本与派生图，靠四件事对齐：

1. **同一段主体描述**：从锚点的提示词复制，不改字
2. **同一光位**：主光方向、色温写死，派生图不换光
3. **同一画幅与背景**：白底就都白底，场景就都场景
4. **并排比对**：两张图左右放，看几何、颜色、印刷、比例

**并排比对是最有效的一招。** 单看一张觉得都对，放一起才发现杯口宽了两毫米、logo 高了一格。

详法见 `references/acceptance.md`。

## 六、自检（可跑脚本）

```bash
python scripts/check_assets.py --dir <制作目录>
```

四条判据：

| # | 判据 | 级别 |
|---|---|---|
| A1 | 清单里每个编号都有对应文件 | 致命 |
| A2 | 文件名符合 `<编号>_<用途>_v<N>` | 致命 |
| A3 | 目录里没有清单外的孤儿文件 | 告警 |
| A4 | 每张图分辨率 ≥ 短边 720 | 告警 |

退出码：`0` 通过 / `2` 有致命项 / `3` 读不了目录。

---

## 七、边界

- **不写分镜**：资产需求从分镜表与清单来，自己不改内容
- **不写视频提示词**：那是上游的事，本技能只补图像提示词
- **不生成视频**：只处理静态图
- **不替代用户验收**：Agent 按七项做技术/一致性复核，最终采用以 G3-A 用户批准为准
- **不保证一次出对**：每次只生成一版，失败后按具体缺陷生成下一版
