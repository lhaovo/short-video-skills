# 资产准备台

视频生成能不能接得上，取决于这一步。**要解决的问题只有一个：让同一样东西在每一张图里都是同一样东西。**

输入是资产清单（或分镜表），输出是一批按编号命名、可直接被 `short-video-generate` 当首帧引用的图。

它不写分镜、不切段、不写视频提示词，也不生成视频。它负责「图」这一段。

---

## 一、四条铁律

1. **先锚点，后派生。** 母版没定，不要做角度图。角度图是照着母版长出来的，母版错了全组都错。
2. **一次只改一个变量。** 换角度就不换光，换光就不换角度。两个一起改，出问题分不清是谁的错。
3. **候选只增不覆盖。** `v1`、`v2` 并存，选定哪版写进工单。生成是概率的，删掉旧版等于删掉退路。
4. **图和清单必须对得上。** 编号就是文件名。清单里有 `PR-01`，目录里就得有 `PR-01_*`。

---

## 二、资产分三级

不是每张图都值得同等投入。先分级，再分配精力。

| 级别 | 是什么 | 例 | 要求 |
|---|---|---|---|
| **锚点级** | 全片身份基准，被多处引用 | 产品主图、人物三视图、主场景全景 | 最严：多候选、逐项验收、定版后不再改 |
| **派生级** | 从锚点长出来的角度、状态、细节 | 产品背面、开盖状态、手部特写 | 必须与锚点并排比对 |
| **一次性** | 只出现一次，不影响一致性 | 空镜、光效、转场素材 | 过得去就用，不必多候选 |

**分级错了会浪费：** 把空镜当锚点做，一条 30 秒的片子会卡三天；把产品主图当一次性做，后面每段都得重来。

## 三、来源：三种都行，看用途选

| 来源 | 什么时候用 | 要注意 |
|---|---|---|
| **实拍** | 有实物、要准确、涉及参数或功效 | 最好，但要有素材 |
| **AI 生成** | 无实物、虚构场景、氛围、人手 | 要锁几何与印刷，多候选 |
| **官方素材** | 品牌方提供的主图、包装图 | 直接当锚点，最稳 |

**不强制实拍。** 纯 AI 生成的片子，整套资产都可以是 AI 出的，只要内部一致。

### 一个必须提前说清的风险

如果这条片子**要对观众宣称具体参数或功效**（容量、时长、成分、效果），而画面里的产品是 AI 生成的，那画面与宣称之间就对不上——轻则被评论区指出，重则构成虚假宣传。

处理方式只有一条：**有宣称，产品画面就用实拍或官方素材；没有宣称、纯氛围或虚构内容，AI 生成完全够用。**

这一条在开工前问一句就行，不要等成片了才发现。

### AI 生成怎么跑

用自带的 `scripts/kie_gen.py`（KIE GPT Image 2），提交、轮询、下载、按命名落盘一次做完：

```bash
# 文生图（分辨率不写就是 1K，够用）
python scripts/kie_gen.py generate --prompt "…" --ratio 9:16 \
  --out 04-素材/01-资产图/PR-01_产品主图_v1.png

# 图生图：拿锚点当参考
python scripts/kie_gen.py generate --prompt "…" --ref PR-01_产品主图_v1.png \
  --out 04-素材/01-资产图/S01_f01_v1.png

# 批量：读 JSON 任务表（默认 5 路并发）
python scripts/kie_gen.py batch --tasks tasks.json --out-dir 04-素材/01-资产图 --dry-run
python scripts/kie_gen.py batch --tasks tasks.json --out-dir 04-素材/01-资产图
```

分辨率默认 **1K**：这些图最终会被视频模型重采样，源图做大了不保留细节，只增加失败率。要单独放大裁切（做封面）或做白底母版二次利用时，才加 `--resolution 2K`。

批量默认 **5 张同时跑**。出图要 10–40 秒，串行跑 6 张就是三四分钟纯等；5 并发跑 6 张，总时长约等于最慢那张加一轮。被限流（`code != 200` 或 429）就 `--concurrency 2`，**不要因为限流去改提示词**。

四条纪律：

1. **先 `--dry-run`** 看请求体，再真跑。一次批量提交二十张，参数错了就是二十次浪费
2. **密钥只走环境变量** `KIE_API_KEY`，不写进脚本、任务表、工单
3. **先出锚点、确认风格**，再批量派生。锚点级建议降并发逐张看
4. **记 taskId**，写进工单，后面要重抽同一张可以对照查

写法、参数限制、失败处置见 `references/ai-generation.md`。

## 四、七步流程

```
1 读清单 → 2 排顺序 → 3 定级 → 4 出候选 → 5 验收 → 6 落盘 → 7 回写
```

### 第 1 步 · 读清单

从 `02-资产清单.md` 读编号、类型、用途、来源、引用段。

清单里没有图像提示词的，用 `references/prompt-fixups.md` 的四类骨架补写；有的直接取用，不要重写。

### 第 2 步 · 排生产顺序

```
锚点级 → 派生级 → 一次性
```

同类里再按被引用次数排，引用越多的越先做。理由：引用多的资产一旦返工，牵连的段最多。

### 第 3 步 · 定级

每个编号标一个级别（锚点 / 派生 / 一次性），写进工单。这一步只需一分钟，但决定了后面花多少候选。

### 第 4 步 · 出候选

| 级别 | 候选数 | 说明 |
|---|---:|---|
| 锚点级 | 4–6 | 挑一张定版，其余留作备选 |
| 派生级 | 2–3 | 与锚点比对后选 |
| 一次性 | 1–2 | 能用就行 |

出图前先确认三件事：画幅对不对、背景对不对（白底还是场景）、有没有多余元素（文字、水印、手）。

用 AI 生成时，先 `--dry-run` 看参数，再按锚点 → 派生的顺序提交，一批 4–6 张。

### 第 5 步 · 验收

按 `references/acceptance.md` 的七项逐条过，七项里过六项才能留，关键项（几何、印刷）不过直接打回。

### 第 6 步 · 落盘

```
04-素材/01-资产图/
├── PR-01_产品主图_v1.png
├── PR-01_产品主图_v2.png   ← 备选，不删
├── SC-01_办公桌面_v1.png
└── CH-01_女性手部_v1.png
```

命名格式：`<编号>_<用途>_v<N>.<ext>`。编号与清单一致（状态后缀 A/B 保留），用途 2–8 字、可用下划线细分，版本递增。

### 第 7 步 · 回写

清单状态改成「已有 / 已有备选 / 待补」，并在工单里记下选定版本。**不回写，下一步就不知道该引用哪一版。**

## 五、一致性怎么保

同一编号的多张图，靠四件事对齐：

1. **同一段主体描述**：从锚点的提示词复制，不改字
2. **同一光位**：主光方向、色温写死，派生图不换光
3. **同一画幅与背景**：白底就都白底，场景就都场景
4. **并排比对**：两张图左右放，看几何、颜色、印刷、比例

**并排比对是最有效的一招。** 单看一张觉得都对，放一起才发现杯口宽了两毫米、logo 高了一格。

详法见 `references/acceptance.md`。

## 六、自检（可跑脚本）

```bash
python scripts/check_assets.py --dir <制作目录>
```

五条判据：

| # | 判据 | 级别 |
|---|---|---|
| A1 | 清单里每个编号都有对应文件 | 致命 |
| A2 | 文件名符合 `<编号>_<用途>_v<N>` | 致命 |
| A3 | 目录里没有清单外的孤儿文件 | 告警 |
| A4 | 每张图分辨率 ≥ 短边 720 | 告警 |
| A5 | 锚点级资产候选数 ≥ 2 | 告警 |

退出码：`0` 通过 / `2` 有致命项 / `3` 读不了目录。

---

## 七、边界

- **不写分镜**：资产需求从分镜表与清单来，自己不改内容
- **不写视频提示词**：那是上游的事，本技能只补图像提示词
- **不生成视频**：只处理静态图
- **不替代判断**：验收标准给了，但「这张能不能用」最终由人定
- **不保证一次出对**：生成是概率的，本技能保证的是「有候选、有验收、有版本」
