# AI 生成资产

没有实拍素材时，人物、场景、道具、产品都能用 AI 生成。这份文件管「怎么调、怎么写、怎么批量、怎么收拾失败」。

---

## 一、什么时候可以交给 AI

| 资产 | 能 AI 出吗 | 条件 |
|---|---|---|
| 场景、空镜、氛围 | ✅ 完全可以 | 无 |
| 人物（三视图、手部、表情） | ✅ 可以 | 用参考图锁身份 |
| 道具、图形 | ✅ 可以 | 无 |
| 产品本体 | ✅ 可以，但**有条件** | 没有参数/功效宣称时；要锁几何与印刷 |
| 白底母版图 | ✅ 可以 | 多出候选，挑结构最稳的 |
| 画面里的文字、logo、刻度 | ❌ 不要 | 模型必写错，交给后期图层 |

一句话判据：**这张图会被人拿去核对具体数字或文字吗？** 会，就别交给 AI。

## 二、参数怎么定

| 参数 | 取值 | 建议 |
|---|---|---|
| 比例 | 9:16 / 3:4 / 1:1 / 4:3 / 16:9 | 竖屏短视频用 9:16；小红书可用 3:4 |
| 分辨率 | 1K / 2K / 4K | **默认 1K，够用**。只有要放大裁切或做白底母版才升 2K；4K 很少需要 |
| 参考图 | 图生图时传 | 先传身份锚点，再传场景；顺序影响权重 |

两条硬限制，写进脚本里了：

- `1:1` 不能配 `4K`
- 比例 `auto` 只能 `1K`

超了会直接报错，不要试。

**为什么默认 1K 就够**：这些图最终是喂给视频模型的参考图或首帧，模型会把它重采样到自己的目标尺寸。源图做到 2K、4K，进模型后并不保留多余细节，反而出图更慢、更容易在细节上生成错东西。真正决定成片清晰度的是视频模型那一端，不是这张参考图。

需要升分辨率的只有两种情况：这张图要单独拿去放大裁切（比如做封面），或者白底母版需要抠图后二次利用。

和校验脚本的关系：`check_assets.py` 的 A4 判据是短边 ≥720px（告警级）。1K 出图的短边一般就在这附近，偶尔会踩线报警——这种告警先看一眼实际尺寸，短边 640–719 的图喂视频模型通常还能用，不必立刻升 2K；短边低于 640 才需要重出。

## 三、提示词怎么写（和 MJ / SD 不一样）

GPT Image 2 这类模型读**完整句子**，不是关键词堆。堆一串 `cinematic, 8k, masterpiece` 不如一句「左侧窗光斜射，杯身有一道窄高光」。

### 顺序

```
画幅比例 → 主体是谁 → 在做什么/什么状态 → 环境 → 光线 → 材质 → 风格 → 约束
```

### 与视频提示词的三点不同

| | 图像提示词 | 视频提示词 |
|---|---|---|
| 负向词 | **可以用自然语言否定**：「画面中不要出现文字和水印」 | 基本不用，改描述想要的 |
| 动作 | 写**一个静态瞬间**（正在拧开盖子） | 写**动作过程 + 时间轴** |
| 长度 | 可以更长，细节越具体越稳 | 一屏以内，超过就要拆段 |

### 一个反直觉的点

**中文提示词在 GPT Image 2 上可用**，但风格词与材质词用英文更稳（`matte finish`、`soft diffused light`）。混写是正常做法，不必强行全英文。

## 四、四类资产的写法要点

骨架在 `prompt-fixups.md`，这里只记 AI 生成特有的几处。

### 4.1 人物三视图

- 三张（正/侧/背）**共用同一段人物描述**，只改视角词
- 中性表情、自然站立、正面平视——资产图不要有情绪和动作
- 皮肤高频要压：这张图要喂视频，毛孔与油光会逐帧变成噪点

### 4.2 产品白底

- 一定写「纯白无缝背景」+「背景无投影」，否则出灰底
- 金属写「哑光、低反光」，否则高光吃掉结构
- 45 度是折中角度：正视太平、斜视易变形

### 4.3 场景

- 先写空间体量与结构，再写物件；反过来会得到一堆悬浮道具
- 写空气状态（薄尘、湿气），比堆形容词有用

### 4.4 首帧（图生图）

- 拿产品母版当参考图，提示词只写**场景与光线**，不要重复描述产品长什么样
- 模型已经「看见」参考图，重复描述反而会改它的形状
- 加一句「产品边缘清晰，与背景分离」，防融进背景

## 五、批量怎么跑

单张用 `generate`，一批用 `batch`。任务文件是 JSON 数组：

```json
[
  {"out": "PR-01_产品主图_v1.png", "prompt": "…", "ratio": "9:16"},
  {"out": "SC-01_办公桌面_v1.png", "prompt": "…", "ratio": "9:16"},
  {"out": "S01_f01_v1.png", "prompt": "…", "ratio": "9:16", "ref": ["PR-01_产品主图_v1.png"]}
]
```

`resolution` 不写就按 1K 出。要单独放大裁切的图，才在这一条里加 `"resolution": "2K"`。

```bash
# 先看请求体，不花钱
python scripts/kie_gen.py batch --tasks tasks.json --out-dir 04-素材/01-资产图 --dry-run

# 确认后真跑，默认 5 路并发
python scripts/kie_gen.py batch --tasks tasks.json --out-dir 04-素材/01-资产图

# 被限流就降并发
python scripts/kie_gen.py batch --tasks tasks.json --out-dir 04-素材/01-资产图 --concurrency 2
```

### 并发怎么理解

默认 **5 张同时跑**。出图本身要 10–40 秒，串行跑 6 张就是三四分钟纯等；5 并发跑 6 张，总时长约等于最慢那张加一轮。

| 并发 | 适合 | 代价 |
|---:|---|---|
| **5**（默认） | 一般情况 | 偶发限流 |
| 2–3 | 被限流、或要边跑边看质量 | 慢，但稳 |
| 1 | 排错、单张重抽 | 最慢，最好定位 |

**限流的表现是 `code != 200` 或 HTTP 429**，不是"图片质量差"。看到这类报错先降并发，不要去改提示词。

四条批量纪律：

1. **先跑锚点，再跑派生。** 风格没定就批量，等于批量返工。锚点级建议 `--concurrency 1` 或 2，逐张看
2. **一批 4–6 张**，跑完就验，不要一次提交二十张
3. **失败不中断**（默认继续），最后看汇总里的 failed；要"一错就停"加 `--stop-on-error`
4. **记下 taskId**，写进工单——后面要重抽同一张，可以对着查

**并发时工单要一次回写，不能跑一张写一张。** 五张同时结束，五次写入会互相覆盖，最后工单上只剩一张的记录。正确顺序是：跑完 → 收下脚本输出的 `items`（已按任务表顺序排）→ 一次性补齐工单 → 核对行数与任务数一致。

想边跑边记，就把 `--concurrency` 设成 1。**「并发 + 零散写」是最坏的组合**：又慢又不准。

汇总里的 `items` 按**任务表顺序**排，不是按完成顺序。所以对着清单核对时不用重新排序。

## 六、成本与时间

| 项 | 量级 |
|---|---|
| 单张生成 | 10–40 秒 |
| 单张失败重试 | 通常 1–2 次内成功 |
| 一条 30 秒片子的资产 | 锚点 2–3 张、派生 3–5 张、一次性 2–3 张 |

时间主要花在**挑选与返工**上，不在生成本身。所以先定级、定候选数，比调参数更省时间。

## 七、失败怎么收拾

| 现象 | 原因 | 改法 |
|---|---|---|
| 报「不支持 1:1 转 4K」 | 参数组合非法 | 换比例或降回 1K |
| 报「auto 只能 1K」 | 显式指定了更高分辨率又没给比例 | 写死 9:16，或去掉 `--resolution` |
| 任务成功但没图 | 提示词被安全策略拦了 | 改中性描述，去掉敏感词 |
| 出图比例不对 | 只在请求里写了比例，提示词里又说了别的 | 两边保持一致 |
| 参考图没起作用 | 只写了「参考这张」，没说继承什么 | 写清「保持产品外观，只换背景」 |
| 主体变形 | 参考图混了风格与内容 | 一张图只给一项职责 |
| 反复被拒 | 提示词里出现人物身份、医疗、暴力类描述 | 改为中性场景描述 |

## 八、三条安全线

1. **密钥只在环境变量里**（`KIE_API_KEY`）。不写进脚本、不写进 tasks.json、不写进工单、不打印
2. **不把敏感图传到第三方**：身份证、人脸特写、未公开产品。要传就传已确认可外发的素材
3. **生成内容发布时按平台要求标识**，这条在发布环节做，但资产阶段就要留痕（哪几张是 AI 生成的，写进工单来源列）

## 九、脚本能给什么、不能给什么

能给：提交、轮询、下载、按命名落盘、批量、查任务。

不能给：**判断这张图能不能用**。生成只是把候选做出来，留下哪张仍然按 `acceptance.md` 的七项人工过。
