# 生产作业

配合 SKILL.md 的七步流程。这份文件管「怎么把一批图高效地做出来，并且不丢不乱」。

---

## 一、读清单时看四件事

| 看什么 | 用来决定 |
|---|---|
| 编号与类型 | 分组，同类一起做 |
| 被哪些段引用 | 排序，引用多的先做 |
| 来源（实拍 / AI / 官方） | 走哪条生产路径 |
| 是否已有 | 已有的直接验收，不重出 |

清单里缺「用途」这一列的，先补上——用途是命名的一半（`PR-01_产品主图_v1`），也决定画幅。

---

## 二、生产顺序：按依赖排，不按列表顺序

```
产品主图 ──┬──→ 产品角度图
           ├──→ 产品细节图
           └──→ 首帧图（与场景合成）

空间结构母版 ──→ 机位子母版 ──→ 首帧合成

人物三视图 ──→ 人物表情 / 手部 / 服装细节
```

规则三条：

1. **锚点先做**，派生照它长
2. **同组连续做**，不要产品做一半去跳场景——换了工具参数再回来，色调就对不上了
3. **首帧最后做**，它依赖产品与场景两边的资产

### 场景资产的两层结构

当同一地点被多个镜头复用时，空间一致性和机位变化要分别管理：

- **空间结构母版**只锁空间不变量：地面/墙面材质、建筑体块、橱窗形态、固定背景结构、空间纵深关系、主光源来源和大致方向。它不锁具体机位、景别、人物、动作或临时道具。
- **机位子母版**是同一空间下的无人空镜，按实际分镜需要制作。可用正打全景、过肩/侧位近景、俯拍队列、低角度仰拍、门口/鞋架特写等视角。首帧应引用对应子母版，而不是全部从一张空间母版派生。
- 不同机位可以有不同画面内阴影形状，但不能丢掉同一空间的材质、体块、纵深和主光来源。正午/傍晚等光照变体只在剧情跨时段时制作。

验收顺序：先并排检查空间结构母版与代表性机位子母版，再检查由各机位派生的首帧。母版降低漂移，不保证模型逐像素复现；若仍漂移，换参考图或生成方案，不继续盲目重抽。

## 三、定级：三个判据

| 判据 | 说明 |
|---|---|
| 被引用次数 | ≥3 段 → 锚点级 |
| 是否承载身份 | 产品本体、主角脸、主场景 → 锚点级 |
| 出错代价 | 错了要牵连重做的，升一级 |

反过来，只出现一次、不影响其他图的，一律按一次性处理。

**默认不要全按锚点做。** 一条 30 秒的片子，锚点级通常只有 2–3 个（产品、主场景、可能一个人物），其余都是派生或一次性。

## 四、一次只生成一张

每个资产编号先只提交一个任务、只生成一张图。锚点、派生和一次性都不预先批量生成候选。

```text
生成 v1 → 验收 → 通过则落盘
                ↘ 不通过 → 记录缺陷 → 改一个变量 → 生成 v2
```

### 什么时候生成下一版

只有当前版本存在明确不合格项时才重试，例如：

- logo 缺笔画或变形；
- 手指数量错误；
- 主体结构、服装或空间关系不一致；
- 画幅、背景、光位与资产契约不符。

“看着不够高级”不是缺陷。此时先检查提示词和参考图，不能无目的地连续重抽。

**下载失败不算内容失败，不生成新版本。** SSL、连接重置、URL 过期都先查询原 taskId 并重新下载；只有图片已经拿到、验收发现画面缺陷时，才进入下一版。

### 反复出不对时的换变量顺序

```
提示词措辞 → 参考图 → 画幅与构图 → 生成模式 → 换工具
```

一次只换一个。三个一起换，出了好图也不知道为什么好。

## 五、落盘与命名

### 目录

```
04-素材/01-资产图/
```

首帧图放 `04-素材/02-首帧/`，不混在资产图里——首帧是「段」的属性，资产是「片」的属性。

### 命名

```
<编号>_<用途>_v<N>.<ext>
```

| 部分 | 规则 | 例 |
|---|---|---|
| 编号 | 与清单完全一致，大写；状态后缀 A/B 保留 | `PR-01`、`CH-01A` |
| 用途 | 2–8 字，需要更细可用下划线连接 | `产品主图`、`身份锚点`、`丁克大脚丫_身份锚点` |
| 版本 | `v1` 起，递增 | `v3` |
| 扩展名 | 保留原格式，不转来转去 | `.png` / `.jpg` |

对：

```
PR-01_产品主图_v1.png
PR-01_产品主体_侧面_v1.png
SC-01_办公桌面_v1.png
CH-01_女性手部_v1.jpg
```

错：

```
产品图.png              ← 没编号，下游不知道挂哪
PR-01.png               ← 没用途，多角度会互相覆盖
PR-01_产品主图_final.png ← 用了 final，就没有 final2 的余地
PR-01_产品主图_v1 (1).png ← 系统重名后缀，脚本不认
```

**不用 `final`、`new`、`最新`。** 版本号是唯一可靠的东西。只有重试时才递增到 `v2`、`v3`。

### 不删旧版

失败版本的记录可以保留，方便追溯为什么重试；但第一轮只生成 `v1`，不把未采用的版本当作并行候选。

## 六、回写清单

每张图落盘后，改三处：

| 改哪 | 改成什么 |
|---|---|
| 状态列 | 已有 / 待补 |
| 工单的采用版本 | `v1`；重试后才改为 `v2`、`v3` |
| 备注 | 缺什么、为什么 |

状态只有「已有 / 待补」两种。「差不多能用」仍然是「待补」。

taskId 由脚本在提交成功后自动写入 `04-素材/00-生图任务/`，不等到图片下载成功才记。工单状态只表示图片是否已有并通过验收；下载中断看任务记录，不能据此重提。

---

## 七、中途换工具怎么办

换模型或换工具时，一致性最容易断。三条：

1. **先拿已定版的锚点重跑一次**，看新工具出的是不是同一个东西
2. 如果差异明显，**锚点不换**，只让新工具做派生；派生图仍先单张生成，不合格再重试
3. 记录换工具的时间点，写进工单备注——后面出问题好定位

## 八、时间分配的实话

一条 30 秒、4–5 段的片子，资产阶段的真实比例大概是：

| 环节 | 占比 |
|---|---|
| 逐张生成 | 45% |
| 验收与比对 | 25% |
| 命名落盘与回写 | 5% |
| 失败重试 / 补拍 | 25% |

**验收与重试占主要时间。** 每次只生成一张，问题定位更清楚；不合格时只改一个变量再生成下一版。
